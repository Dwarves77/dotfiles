# Operator ruling, 2026-09-06 — the four review queues and R-A / R-B / R-E

recommended_decision; for every DISAGREE group ... decide from evidence, not from either prior

## Mechanism

For each of the four ratification queues, every group whose `recommended_decision` (the queue's own
deterministic rule) already equalled Haiku's `proposed_decision` was accepted as-is (no re-litigation).
Every DISAGREE group was decided independently from evidence: the group's sample URLs/titles already
captured in the digest, spot-verified with live `WebFetch` on the highest-volume and most ambiguous
groups (`cer-rec.gc.ca::guidance_path`, `canada.ca::guidance_path`), and cross-checked against
`src/lib/sources/host-authority.ts`'s officialness class table where host identity mattered. No group's
`decision` was left `null`.

## R-B — the oil-bulletin `market_signal` rows

**Ruling**: reclassify (on_vertical), not archive — these are the EU Weekly Oil Bulletin price series
(Euro-Super 95, diesel, heating gas oil, LPG, residual fuel oil, heavy fuel oil), genuinely on-vertical
freight-fuel price data (mechanism: PRICES freight fuel cost, one of `screen-rules.mjs`'s own five
mechanism prongs).

**Live-verified count [CONFIRMED, read-only SQL, project kwrsbpiseruzbfwjpvsp, 2026-09-06]**: **6** rows,
not 7 — `intelligence_items` WHERE `item_type='market_signal'` AND `source_url ilike
'%weekly-oil-bulletin%'`, all `is_archived=false`, all sourced from
`https://energy.ec.europa.eu/data-and-analysis/weekly-oil-bulletin_en` (ids: `4fae403a`, `70869a22`,
`32783a47`, `2d306cc6`, `0ee667cc`, `180b8163`). The brief's count of 7 does not match live data; reported
as measured, not silently corrected to match the brief (rule 4).

**The mechanism gap [CONFIRMED]**: the brief's suggested fix — a `reviewed-verdicts.json` entry, in the
format `loadReviewedVerdicts` reads (keyed by `census_worklist.id`) — **cannot bind these six rows**.
`screen-reconcile-records.mjs` joins a live item to its census row by `source_url`
(`census_worklist WHERE document_url = intelligence_items.source_url`); a live query confirms **zero**
`census_worklist` rows exist for `weekly-oil-bulletin_en` (these six were minted directly as an R-D
`rows_file` batch, bypassing the census table entirely — `docs/ops/session-log.md` addendum
"RD: the six oil-bulletin series items as a `rows_file` batch"). With no census row, `classifyLiveRecords`
passes `census?.id ?? null` → `null` into `screenVerdictFor`, whose reviewed-override lookup
(`row?.id ? reviewed?.[row.id] : null`) short-circuits to `null` on a null id — a `reviewed-verdicts.json`
entry for these items would never be read, at any key. Writing one anyway would need a fabricated
census id, which rule 2 forbids.

**What the rule engine actually returns today [CONFIRMED, `node -e` against the live `classifyRelevance`
export, all six titles/URLs]**: `ambiguous` / `no_signal_ambiguous` for all six — no `ON_VERTICAL` or
`OFF_VERTICAL` rule in `screen-rules.mjs` matches "EU Weekly Oil Bulletin" or the
`weekly-oil-bulletin_en` URL path. Practically this means the six rows are **not at risk of archival
today** — `screen-reconcile-records.mjs` only archives `off_vertical` verdicts; `ambiguous` is left live
and merely listed for a ruling, which is what would happen to these six (with `census_id: null`) on the
next dispatch. But "safe by default" is not the same as "correctly classified," and the ambiguous bucket
is not itself a home for six specific, ruled-on-vertical rows.

**No file written for this ruling.** A `reviewed-verdicts.json` entry cannot enact it (mechanism gap
above), and RULINGS-TRANSCRIBE writes no code. **The dispatch-ready fix**: add one `ON_VERTICAL` rule to
`fsi-app/scripts/mint/screen-rules.mjs` matching `document_url` against
`/energy\.ec\.europa\.eu\/data-and-analysis\/weekly-oil-bulletin/i` (or `title` against `/weekly oil
bulletin/i`), with `mechanism: "PRICES: EU Weekly Oil Bulletin sets the benchmark before-tax EU-average
price for automotive/heating/marine fuel oils — a direct freight-fuel-cost price series"`. That is a
`screen-rules.mjs` code change, one line plus its required `mechanism` annotation
(`screen-rules.test.mjs`'s own meta-test enforces the annotation) — named here as the exact next dispatch
for a code lane, not executed by this lane.
