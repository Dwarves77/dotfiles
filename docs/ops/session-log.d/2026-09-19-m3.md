### Stop, reported not solved (Amendment 1 item B, the rest)

`resolveLoopRunId`'s match-by-`config.loop_run_id` mechanism is sound for exactly ONE hop: a family
directly off `source-sweep` (fetch-drain, ledger-consume), because `source-sweep.yml`'s own "Resolve
loop_run_id" step stamps `config.loop_run_id` to its OWN `github.run_id` whenever the operator leaves the
input blank  --  so `config.loop_run_id` genuinely IS "the recorded GitHub run id of the run that wrote it"
for that one family. It does NOT generalize past hop 1: once a downstream hop PROPAGATES the shared
loop_run_id forward (so its own artifact carries the ORIGINAL sweep's id, never its own actual GitHub
Actions run id), no artifact anywhere records that hop's own run id, so a consumer one hop further down
(the population-turn/corpus-turn mint runner reading ledger-consume's loop_run_id; the downstream-chain
artifact writer reading population-turn's or corpus-turn's loop_run_id) cannot match "the artifact written
by GitHub run id X" against anything  --  `resolveLoopRunId` correctly returns null there (never invents),
which means the propagation silently stops at hop 1 today. Closing this requires either a new field
recording each run's own actual GitHub Actions run id in every artifact (a cross-cutting schema addition
touching 4+ governing files), or wiring bash/jq extraction of the upstream's already-known
`config.loop_run_id` directly into each consuming workflow's own resolve step (mirroring
`population-turn.yml`'s/`downstream-chain.yml`'s existing "THE MECHANISM" artifact-fetch blocks) and
passing it through as `resolveLoopRunId`'s `explicit` argument  --  either is a design decision the brief did
not make. I did not wire `config.max_items`/`config.upstream_run_id`/`config.loop_run_id` into the mint
runner's own artifact (`run-mint-batch.mjs`) for the same coupled reason (item 3's own sentence names all
three together, and the runner's own artifact schema is a governing file I did not want to touch on an
unauthorized design). Reported for the coordinator to pick a mechanism and re-dispatch.
