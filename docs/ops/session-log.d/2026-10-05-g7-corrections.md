## API contract for lane G7-UI (full text at the top of `logic.mjs`)
- All routes: platform admin only (401, 429, 403 from `requireAdminRoute`), rate-limit headers on every response. Errors are `{ error, code }`.
- `GET /api/admin/items/{itemId}/corrections` -> 200 `{ item_id, counts: {active, revoked}, corrections: [ {id, item_id, target_kind, target_ref, op, value, machine_value, reason, created_by, created_at, revoked_at, revoked_by, revoked_reason, active, superseded, latest_machine_value, machine_observed_count, machine_observed_at} ] }` newest first; 404 `item_not_found`.
- `POST /api/admin/items/{itemId}/corrections` body `{ target_kind, target_ref, op, value?, reason }` (reason mandatory, `created_by` never read from the body) -> 201 `{ id, item_id, applied: true }`; 400 `reason_required|target_kind_invalid|op_invalid|target_ref_required|target_ref_invalid|value_invalid|fact_needs_span|invalid_json`; 404 `item_not_found|claim_not_found|section_not_found`; 422 database refusals (`fact_span_not_verbatim`, `fact_failed_validation`, ...).
  - target_ref: fact = claim id, tag = `<topic_tags|operational_scenario_tags|compliance_object_tags>:<tag>`, connection = the other item id, section_text = section_key, full_brief = `full_brief`.
  - ops: fact suppress|replace, tag add|remove, connection add|remove, section_text replace ({content_md}), full_brief replace ({text}); fact replace value {source_span, search_result_id, claim_text?, source_id?}.
- `POST /api/admin/items/{itemId}/corrections/{correctionId}/revoke` body `{ reason? }` -> 200 `{ id, item_id, revoked: true }`; 409 `correction_not_active`.

## Decisions
- A fact `add` is not offered (a claim belongs to a section and the validator needs its slot and label context); recorded in the migration header.
- Revoke stops enforcement only. A tag, brief or section keeps its corrected value until the next machine write; a suppressed claim reappears at once; a removed edge returns on the next discovery pass; a manual edge stays until a later remove. Restoring data on revoke was not built (untestable without a database and not in the brief).
- `item_id` on the table is a soft reference (no FK), same as `claim_versions` (208), so the trail survives an item delete.
- Audit: `intelligence_item_versions` (053) trigger `intelligence_items_version_snapshot` is defined only in 053 and no later migration in the tree drops it; its WHEN clause covers full_brief and topic_tags but not the other two tag columns, and it records no actor. Live status not verified (no database access). `item_corrections.created_by` is the actor trail.
