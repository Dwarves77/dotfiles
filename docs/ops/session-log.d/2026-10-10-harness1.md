## Accomplished

1. Mode defect [CONFIRMED by reading the code and the population-turn step]: `run-mint-batch.mjs` derived `config.mode` from `--execute`, and `population-turn.yml` always passes `--execute` (it only means "write this invocation's output files"), so a run the chained dry-run guard forced to dry was recorded `execute` (population turn 38058506216, `mint-run-004`). Fix at the root: `--run-mode dry|apply` carries the RESOLVED mode (`$RUN_MODE`, after the guard) into `buildRunArtifact`; `config.mode` is `dry` for a dry run and `execute` for apply (the vocabulary `upstream-artifact.mjs` APPLY_EVIDENCE and `assemble-train.mjs` read), and `config.run_mode` records the resolved value. Without `--run-mode` (a hand run, no guard) the old execute/dry_run pair is unchanged. A bad value is a usage error. The workflow call site passes `--run-mode "$RUN_MODE"`.
2. Id defect [CONFIRMED by reading `claimRunId` against `recordHarnessRun`]: two numbering authorities (the directory's own max+1 and `harness_runs`' own max+1) left the file under the loser's name. `recordHarnessRun` now takes `artifactPath`: before the insert it skips any ledger number whose filename another artifact already holds in that directory (never clobbers a committed run), after a landed insert it renames the file to the landed id and rewrites its `run_id`; a failed insert leaves the file untouched; a landed row whose file cannot be reconciled returns `artifact_error` and `runCli` exits 1. `runCli` passes `--file` as `artifactPath`; `dry-run-structured-actions.mjs` passes its artifact path and returns the landed id and path.
3. Consequence to know: in CI, where committed `mint-run-001..028` exist and `harness_runs` is behind, the next mint ledger id is the first free number above the ledger max, i.e. it follows the directory (029), not 005. Ids stay unique and monotonic per family; nothing in F28 or the ledger export requires contiguity (grep of F28, export-harness-ledger, run-artifact for gap rules: none).
