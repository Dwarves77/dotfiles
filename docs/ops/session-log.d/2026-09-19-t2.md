## 2026-09-19, lane T2: one guarded env-file loader; F48 refuses a bare load

Sonnet executor lane, worktree `.worktrees/wt-t2`, branch `lane/t2-env-file-loader-2026-09-19`, cut from
master `25418482`.

**What happened [CONFIRMED against the 2026-09-19 handoff addendum].** This is the second occurrence of the
same defect class in two days. On 2026-09-18 (lane T1), `check-vocabulary-drift.test.mjs` failed only in
`wt-session-d`, the one worktree carrying a real `fsi-app/.env.local`, because the script loaded that file
from disk on its own and handed the stripped-out credential variables straight back to the child, so the
expected self-skip never happened. On 2026-09-19 at 10:40:37 EDT (per the addendum, from the coordinator's
queue log), lane M2's push was refused by a second, different script with the exact same shape:
`ecb-fx-producer.mjs` also loaded `.env.local` from disk on its own, so its own no-credential test failed in
that same worktree and nowhere else. By the operator's ruling, a defect that recurs twice in two days by the
same mechanism gets a class fix, not a second one-off patch.

**The fix.** One home for the env-file load, `fsi-app/scripts/lib/env-file.mjs`: `loadLocalEnvFile()`
(guarded, never throws, honours the one switch `FSI_NO_ENV_FILE`) and `withoutCredentials()` (strips the
five credential variables from a child's env AND sets the switch, so a checkout with an env file cannot hand
them back). Fitness function F48 was rewritten from its original single check (a bare, unguarded
`process.loadEnvFile` crashes with ENOENT on a workflow dispatch) to three checks: (a) no live script may
call `process.loadEnvFile` at all any more, guarded or not, since a try-wrapped bare call was exactly what
let the class exist ninety times over; (b) a test that strips a credential variable by hand, in a test that
spawns a child process, must use `withoutCredentials()`; (c) a test that spawns a child and asserts a
credentials refusal on that child's own result (`.stderr`, `.stdout` or `.status`) must use
`withoutCredentials()` too.

**90 live scripts** under `fsi-app/scripts/**` and `fsi-app/src/**` now call `loadLocalEnvFile()`
[CONFIRMED by `grep -rl loadLocalEnvFile fsi-app/scripts fsi-app/src --include="*.mjs"` excluding test files
and the home module itself: 90]. The archived, reground and scratch trees (`scripts/_archive`,
`scripts/_reground`, `scripts/tmp`, `src/_archive`) and `supabase/seed` are historical and out of scope, by
F48's own scope since lane L41 (nothing there runs in any lane or workflow). Four credential-absent tests
(`ecb-fx-producer.test.mjs`, `refresh-published-price-statistics.test.mjs`,
`check-vocabulary-drift.test.mjs`, `src/__tests__/market-ecb-fx-parser.test.mjs`) build their child
environment with `withoutCredentials()`; lane T1's one-off `CHECK_VOCAB_DRIFT_NO_ENV_FILE` switch is retired
in favour of the one shared switch; two pure-math selftests under `src/lib` no longer load an env file they
never used.

**Two false positives found and fixed while wiring F48's own tests, both the same shape: a per-file
precondition standing in for a per-test-block one.** Check (b), as first written, flagged
`data-public-surface-slugs.test.mjs` for setting and deleting `process.env.SUPABASE_SERVICE_ROLE_KEY`
in-process to unit-test a pure function; no child is spawned there, so no env file could hand anything back.
Fixed by requiring the same spawn precondition check (c) already had. Check (c), as first written, then
flagged `market-eia-v2-petroleum-spot-parser.test.mjs` line 243, a plain assertion on `decideApply()`'s
return value, only because the file separately spawns a child for an unrelated kill-switch test elsewhere.
Fixed by requiring the flagged line itself to reference the spawned child's own result (`.stderr`, `.stdout`
or `.status`), not merely to appear in a file that spawns something somewhere. Both fixes are proven RED
(the original shape still flags a real hand-rolled strip/assertion on a spawned child) and GREEN (the
false-positive shape is clear) in `F48-env-file-load-guarded.test.mjs`.

**What F48 cannot see (its residual) [CONFIRMED by reading the checker's own regex].** All three checks are
single-line, regex-based text scans, not an AST or data-flow analysis. Check (a) misses a call reached
through a locally-renamed re-export of `process.loadEnvFile` rather than the literal name. Check (b) misses
a strip built from a variable holding the credential name (`const k = "SUPABASE_SERVICE_ROLE_KEY"; delete
env[k];`) rather than the literal name on the line. Check (c), as narrowed by this lane's own fix, misses a
credentials assertion whose child-result reference (`.stderr`/`.stdout`/`.status`) sits on a different line
from the assertion itself (`const out = res.stderr; assert.match(out, /DB creds/);`); narrowing check (c)
to require both on one line, which is what removed the false positive, also widens this specific evasion
shape, noted here rather than silently accepted. None of the 90 live scripts or the credential-absent tests
in this tree currently take either shape.
