## 2026-09-22, lane G3b: fix the layout guard's closed-`<details>` false positive UI-75 STOPped on

Brief: dispatch to lane G3b, continuing on `lane/g3-guard-real-fonts` at head `0b29ff0f` (UI-75's
commit). Fixes the 54 false L2/L9 findings UI-75 reported and STOPped on rather than editing, per its
own rule 2 ("never edit the guard on a page-shaped finding; if it looks like a detector defect, STOP
with the element and the measurement").

### Cause

`fsi-app/.discipline/rendering/layout-guard/collect.mjs`'s `visible()` helper (about lines 25-30 before
this change) checked `visibility:hidden` / `display:none` / `opacity:0` and a non-zero
`getBoundingClientRect()`. A CLOSED `<details>` gives its non-summary content a real, non-zero rect in
Chromium (`content-visibility: hidden`, not `display:none`), so `visible()` called it visible and the
L2 (box overlap) and L9 (hit target) detectors flagged it against real content it geometrically
overlaps. `[CONFIRMED by lane UI-75 with a live Playwright probe]`, see
`docs/ops/session-log.d/2026-09-22-ui75.md`: 54 findings on `/settings`, all naming
`button[<jurisdiction label>]` inside `BriefingScheduleSection`'s closed "Jurisdiction weighting"
disclosure.

### Fix

`visible()` in `collect.mjs` now returns false when any of three checks fires, in order: (1) an
explicit ancestor walk for a closed `<details>` whose content the element is not the `<summary>` of
(mechanical, does not depend on a specific browser's `content-visibility` behaviour); (2) the computed
`content-visibility: hidden` value directly; (3) `checkVisibility({ contentVisibilityAuto: true,
opacityProperty: true, visibilityProperty: true })` where the engine exposes it, as a second, more
complete opinion. A `<summary>` inside a closed `<details>` stays visible and its own hit target is
still measured, since it is the one thing the reader can see and click.

No allowlist, no baseline entry, no page change: `SettingsPage.tsx` / `BriefingScheduleSection.tsx` are
untouched, per the brief.

### Proof (attack, red then green)

New test in `layout-guard.npmtest.mjs`, "a closed `<details>` is not visible to the collector; open, it
is; its `<summary>` always is": a fixture page (real chromium, `page.setContent`) with a `<button>`
inside a closed `<details>` geometrically overlapping a sibling `<section>`, and a `<summary
role="button">` labelled "Central America" (the real finding's own label, from UI-75's report).

- Closed: the overlapping button is absent from both the L2 box list and the L9 target list; the
  summary is present in the L9 target list with a real non-zero box. `[CONFIRMED]` red without the fix
  (reverted `collect.mjs` via `git stash`, re-ran the test, `AssertionError: closed details content
  must not be a measured L2 box`), green with it.
- Opened (`details.open = true` via `page.evaluate`): the same button is now present in both the L2 box
  list and the L9 target list. The summary stays present and measured either way.
