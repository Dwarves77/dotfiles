## What changed, by class

- `@typescript-eslint/no-explicit-any`: replaced with real or local interface types across the
  admin, community, resource, settings, sources and ui surfaces. Catch blocks typed via
  `instanceof Error`. A few request-body shapes (`CanonicalSourceReview`, `ProvisionalReviewCard`)
  and one markdown-renderer map (`SectorSynopsis`, now typed against react-markdown's own
  `Components`) gained real interfaces in place of per-call `any`.
- `@typescript-eslint/no-unused-vars`: deleted after confirming no consumer (grepped the full
  symbol across `src/` first) - dead imports, dead destructured props, two intentionally-unused
  callback params whose signature tolerates fewer bound names.
- `react-hooks/preserve-manual-memoization` + matching `exhaustive-deps`: `useWorkspaceTagsFacet`
  (`src/lib/tags/`) was the root cause for four of these (Market/Operations/Regulations ledgers,
  WatchlistSurface) - it returned a brand-new object every render even when nothing in it changed,
  so the compiler's own inferred dependency (the whole object) never matched the deps arrays these
  four files wrote (individual members). Memoized the hook's return once; all four call sites now
  depend on the single `tagsFacet` object. One unrelated instance in `OperationsLedger`
  (`aggregates?.totalJurisdictions` vs the whole `aggregates` object) got the same fix. One
  instance in `RegionDimensionMatrix` (a nested-loop early-return scan the compiler reports it
  cannot preserve regardless of the deps array) got a cited disable.
- `react-hooks/set-state-in-effect`: ~15 instances, all one of two shapes already present
  throughout the codebase and cited as such: (a) an early-return guard that resolves state to
  empty/null/false before the same effect's own async fetch runs, (b) a genuine external-system
  read (localStorage, `document.body`, a poll-on-mount) with no subscription to move it into. Each
  got a one-line citation, never a bare disable.
- `react/no-unescaped-entities`, `@next/next/no-html-link-for-pages`, `prefer-const`,
  `react/display-name`, `jsx-a11y/role-supports-aria-props`: mechanical, no behaviour change.
- `react-hooks/immutability` (`BandGradientRule`): real fix, not a disable - rewrote the
  gradient-stop builder from an outer mutable accumulator to a `reduce`, verified by hand that the
  per-segment `from`/`acc` values are identical.
- `react-hooks/incompatible-library` (`VirtualizedRowList`'s `useVirtualizer`): cited disable,
  TanStack Virtual's own documented API shape.

## Correction (caught by the rendering guard, not by lint or tsc)

Batch 1's `useWorkspaceTagsFacet`-adjacent fix in `NotificationsBell.tsx` added the hook's
`setUnreadCount` to a `useCallback` deps array - correct per the lint diagnostic, which said the
compiler could not preserve manual memoization with the empty array it had. Fixing that lint
finding made the whole component compiler-eligible, and the rendering guard (run after all batches
were committed) then caught a real regression: "notifications[one-row]: unread badge is still
present after Mark all read" and the same for `[extreme]`. Root cause: `useUnreadNotificationsCount`
(`src/lib/hooks/useUnreadNotificationsCount.ts`, outside the original `src/components/**` write
set - flagging the expansion here since the fix could not land without it) returned a plain arrow
function rebuilt every render, never memoized. Wrapped it in `useCallback` (empty deps; it closes
only over the always-stable `useState` dispatch). Re-ran the rendering guard after the fix: PASS,
0 findings beyond the dated layout-guard baseline. This is the one instance this lane found where a
"fix the lint cleanly" change surfaced a pre-existing instability as a real runtime defect; it is
recorded here per the flag-is-a-commitment rule rather than left as a note.
