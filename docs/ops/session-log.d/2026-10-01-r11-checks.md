## (a) F66-clock-fragility.mjs, built, zero live violations

New `.discipline/fitness/functions/F66-clock-fragility.mjs` + `.test.mjs`. Flags a test file where a
top-level `test()` block combines a live clock read (`new Date()` with no arguments, or `Date.now()`)
with a strict-equality assertion (`assert.equal`/`assert.strictEqual`, deliberately excluding
`deepEqual`/`deepStrictEqual`, see below) against a COMPUTED string (`+` concatenation or a
`${...}` template), the shape PR #816 (commit `a68111cf`) hit: `nextMilestoneClause`'s test built its
expected string from a day-distance helper that defaulted to the real wall clock, then compared with
strict equality against a hardcoded `" days"` suffix; the gap to the fixture's fixed date was exactly
1 day on 2026-09-28, the code correctly said "1 day" (singular), and the test's own "1 days" went red.

**Non-overfit check (plan's own acceptance test), both negative controls pass clean, by construction
and asserted in `F66-clock-fragility.test.mjs`:**
- `src/lib/relative-time.npmtest.mjs`, has a live `new Date()` read, but compares only to the plain
  literal `"just now"` (no concatenation/template), so it is not flagged.
- `src/lib/render-clock.npmtest.mjs`, its own red-control test spells the text `new Date()` only
  INSIDE a quoted fixture string (test data describing the hazard it scans other files for), never as
  a real call site; `stripStrings()` blanks quoted bodies before the live-clock scan specifically so
  this cannot be mistaken for a call.

**Two false positives found and fixed during build, before the function was called done (not a
"flag for later", rule 13):** the first version used `assert.(equal|strictEqual|deepEqual|
deepStrictEqual)` as the assertion set. Run against the live tree, it flagged
`scripts/producers/lib/emit-producers-artifact.test.mjs:40` and
`scripts/verify/population-report.test.mjs:744`, both `assert.deepEqual(fn(join(tmpdir(),
"does-not-exist-" + Date.now())), [])`: `Date.now()` builds a unique scratch-path ARGUMENT, and the
comparison is `deepEqual` against a literal `[]`, not a string-equality date assertion at all.
Narrowed `ASSERT_RE` to `equal`/`strictEqual` only (arrays/objects never carry "a date-shaped STRING");
both files are now covered by an explicit regression test (`GREEN: Date.now() used to build a
scratch-dir name...`) so the narrowing can't silently regress back to a false positive.

**Live run:** `node .discipline/fitness/runner.mjs --function=F66` → 643 files checked, 0 violations.
No fix was needed in the live tree beyond the function's own false-positive correction above, the
#816 instance itself was already fixed by commit `a68111cf` before this lane started.

**Registration:** none needed as a separate step. `manifest.mjs` derives the function list from a
directory scan of `functions/*.mjs` (excluding `*.test.mjs`), "a registry is a directory, never a
list" (its own header comment), so dropping the two files in is the whole registration. Confirmed by
running the full suite: `node .discipline/fitness/runner.mjs` → 53 functions checked (up from the
prior 52), F66 included, 0 violations total.
