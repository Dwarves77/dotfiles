## Decisions

- C4: the brief's sentence reads as if worktrees under `.worktrees/`, `.claude/worktrees/`, `work/lanes/` are drift when unlisted. That would invert the existing exemption (20+ lane worktrees, this lane's own, would fail) and contradict the C4 header. Built the reading that matches the stated test and the evaluation finding: the three conventions stay exempt, in-repo unlisted is drift, everything else on the machine is a note. [HYPOTHESIS] the brief's wording is a drafting inversion; the coordinator rules.
- Pre-push step 2c's tombstone comment names the removed command. That text incidentally satisfies F54's substring parity for CI's validate-commits job (without it F54 reports 2 violations on the live tree, confirmed by running its `check()`). The proper fix is a dated F54 EXEMPT_STEPS entry (GATE-3 territory); once it exists the path can leave the comment.
- MCP WRITE per the brief's table no longer includes push_*/merge_*; `push_files` and `merge_pull_request` are now UNKNOWN and ask (a human still confirms; the skill demand no longer denies them). Add the prefixes to `MCP_WRITE_PREFIXES` if the coordinator wants them hard-gated.
- Quoted-string stripping (as briefed) means `psql -c "delete from t"` or `bash -c "git push"` is no longer read as DANGER. Named in the module header as a residual.
- Commit trailer uses the model name given by the session attribution reminder (Claude Sonnet 5.5), not the COMMON.md text.
