- `refetch-capped` `GUARD-1-accepted` KEPT. ADR-016 "Two design questions resolved", item b (the line
  beginning "b. GUARD-1 all-or-nothing pool INSERT") records the pool-insert-size question as a FINDING for
  operator ruling with "no code change is made pending the ruling", and its Drain order step 3 makes EXECUTE
  conditional on the operator lifting the hold. No rule in CLAUDE.md decides it (rules 16 and 18 are about
  cadence and figure sourcing). It is an open ruling, so the token stays until the operator rules.
- `provenance-heal` `+strip-unprovable` KEPT, and it is not a requirement: the step runs and writes
  without it, the suffix only enables prose removal from `full_brief` and the full-brief relabel append.
  CLAUDE.md rule 18 says a figure with no source anywhere stays refused, which supports removal after
  STEP SOURCE and STEP C are exhausted. The remediation-discipline skill (category 26, RD-44/45) says data
  is erased only on proven inaccuracy, with proof preserved. No ADR governs the suffix. Not decided here.
- `review-apply-provisional-sources` RETIRED (coordinator ruling: reading B, no rule ever suspends; the
  accessibility counters are pre-hold evidence under rule 16 and the 2026-09-06 ruling refused suspend on
  that ground). Read `patchForDecision` in `provisional-sources.mjs`: `keep` writes `{status: "active"}`
  only. `resolve-provisional-sources` already promotes the same rows on promote (class table or institution
  match resolves a tier, status active or inaccessible, class tier and bias tags written, a tier_override

  the first branch of the ruling: wrapper, apply script, digest library and tests deleted, step and option
  removed, the digest builder drops the queue, runbook 13 is a RETIRED stub that names section 46.
- Coordinator rulings applied: F28 marker added for the `quarantine-disposition` family; `propose-tags.mjs`
  and `tag-proposals.mjs` flag and note text no longer ask for `ratify:tags`; `coverage-report.json`

- Item 5 (apply-deferrals across dispatches): the `maintenance-step` composite action does NOT upload a
  step artifact; the only upload is one job-level `actions/upload-artifact` over the whole OUT_ROOT at the

  `plan.json` into its out dir (already does), upload that one file as a named artifact

  Needs a workflow input and `actions: read`, so it is a separate lane.

  same one `apply-core` and `build-review-digests` use), so the 'all' dry read is already paged. It is still
