# 2026-10-10, lane MASTER-RED-1 (masterred1-red-master-runs-block): a workflow that is red twice running on master now fails every PR

Defect [CONFIRMED: `gh run list --workflow live-smoke.yml`, coordinator brief]: the production live smoke was red on every deployment from 2026-10-08 13:44 and no gate, lane or report surfaced it. A workflow that is red on master is invisible to a PR because a required check only runs on the PR's own ref.

## Accomplished

1. `fsi-app/.discipline/governance/closure-gate.mjs`: a fifth check, STANDING-RED. For every tracked workflow file it reads the latest completed runs on master through the gate's Actions client; when the two newest executed runs both have a red conclusion (failure, timed_out, startup_failure) the PR fails, and the text lists the workflow, both run ids and both head shas. A PR whose diff touches the workflow file or any file in its harness family's governing_files (via `GOVERNING_FILES`, derived from each `scripts/harness-runs/<family>/family.json`) is exempt for that workflow only. A workflow GitHub reports as `disabled*` is ignored. Wired into `runClosureGate`, the CLI summary and the gate-firings record.
2. The three Actions lookups (`fetchLiveRun`, `fetchWorkflowState`, new `fetchMasterRuns`) now share one client function, `ghActionsApi`; the DORMANT-1 endpoints and argument shape are unchanged, so no second client exists.
3. `fsi-app/.discipline/governance/closure-gate.test.mjs`: 11 fixture tests on a fake Actions client (no live call): one red plus one green passes (both orders, a single run, no run); two reds fail with workflow, run ids and shas in the text; timed_out and startup_failure count, skipped and cancelled runs and unfinished runs are not in the sequence; two reds plus a PR touching the workflow passes; a PR touching a governing file passes; unrelated file, another workflow, empty or unreadable diff do not exempt, and the exemption is per workflow; two reds on `disabled_manually` and `disabled_inactivity` pass while `active`, null, `enabled`, empty and `deleted` do not; the gatherer asks the platform state only of a standing red; the endpoint is `runs?branch=master&status=completed&per_page=10` and fails to unknown; the PR diff is read only when `GITHUB_BASE_REF` is set; with no token the live check passes. The existing LIVE combined test now asserts the four tree-derived checks and that `ok` includes STANDING-RED, because the live Actions state of master is outside any diff.

## Decisions

- The workflow already grants `actions: read` to the `test-discipline-engine` job and passes `GITHUB_TOKEN` and `GITHUB_REPOSITORY` to the closure gate step, and `GITHUB_BASE_REF` is set by GitHub in a pull_request run, so `discipline.yml` is not edited.
- `timed_out` and `startup_failure` count as red with `failure`: a workflow that cannot start or times out is as invisible as one that fails. Skipped and cancelled runs did not execute and are not in the sequence (the DORMANT-1 rule).
- No token, an API failure or an unreadable diff is unknown: never a red, never an exemption.
