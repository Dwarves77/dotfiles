## F65-no-bracket-path-tests.mjs, BUILT, plus the runner class fix

**Defect reproduced directly** (not just cited from CF-SEC-11/lane W2-A's prior finding):

```
$ node --test "fsi-app/scripts/__fixture__/[param]/probe.npmtest.mjs"
ℹ tests 0
```

Node's test runner re-parses even an EXPLICIT CLI file argument through its own glob matcher, so a
literal `[`/`]` segment is read as a bracket-expression glob token and matches nothing -- silently, no
error, no nonzero exit. This is a CLI-argument-parsing defect, not a discovery-glob defect: the file
was correctly discovered by `git ls-files`/the filesystem walk in every case tested; it was dropped at
the `node --test <path>` invocation step itself.

**The fix (belt + buckle, per the brief):**
- **Buckle (the class, fixed at the runner):** new `fsi-app/.discipline/lib/run-explicit-tests.mjs`
  executes a NUL-separated file list (stdin) via `node:test`'s PROGRAMMATIC `run({ files, execArgv })`
  API, proven by the same reproduction script to run a `[param]/`-path file correctly (`files` is
  consumed as a literal array, never re-parsed as a glob). Both `fsi-app/.discipline/run-test-suite.sh`
  and `fsi-app/.discipline/hooks/lib/run-npmtest-suites.sh` (and so `.github/workflows/discipline.yml`,
  which calls the latter) now pipe their discovery list through it instead of `xargs -0 node --test`
  or a bare `node --test $files`. `run-npmtest-suites.sh`'s OWN discovery also had the sibling bug:
  `git ls-files 'fsi-app/**/*.npmtest.mjs'` is a git PATHSPEC GLOB, which can mis-match a bracket
  segment the same way; it is now a plain `git ls-files -z -- fsi-app` (no pattern argument) filtered
  by a literal string-suffix `grep`, the same shape `test-discovery.mjs` already used for the no-npm
  suite (which is why `run-test-suite.sh`'s OWN discovery was never actually broken -- only its
  execution step was).
- **Belt (F65 itself):** fails the build the moment any tracked `*.test.mjs` / `*.npmtest.mjs` /
  `*.selftest.mjs` / `*.golden.mjs` path contains a `[` or `]` character anywhere, so a bracket-path
  test is caught by name even if a future caller reintroduces a bare CLI invocation.

**Bracket-fixture proof (brief item 2's explicit ask), executed then removed:**
- Created `fsi-app/scripts/__bracket_proof__/[param]/probe.npmtest.mjs` (one passing test), staged it,
  ran `run-npmtest-suites.sh`: count went from **1545 -> 1546** (ran `sh run-npmtest-suites.sh` twice
  with the fixture present, both times `1546`, exit 0, fixture's own test name present in the spec
  output). F65 correctly flagged the fixture's path as a violation while it was tracked.
- Removed the fixture (`git rm -f` + `rmdir`); re-ran `run-npmtest-suites.sh`, count back to **1545**,
  exit 0; F65 back to 0 violations.
