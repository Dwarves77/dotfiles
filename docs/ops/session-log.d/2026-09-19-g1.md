## 2026-09-19, lane G1: the skill gate judges the acting agent's own transcript

Sonnet executor lane, worktree `.worktrees/wt-landdocs-0911`, branch
`lane/g1-skill-gate-agent-transcript-2026-09-19`, cut from `origin/master`.

**Why.** `fsi-app/.discipline/governance/pretooluse-skill-gate.mjs` denied lane M3's edits to
`fsi-app/scripts/turns/emit-downstream-chain-artifact.mjs` on 2026-09-20 00:55 UTC after the acting
sub-agent had invoked the governing skill twice and read its SKILL.md twice. `.gate-audit.log` (main
checkout) records 8 `Edit deny edit-governed-skillmissing` and 3 `Write deny` entries in the minutes the
sub-agent worked, while the main session made no edits at all.

**Facts, read-only [CONFIRMED unless noted]:**
1. [CONFIRMED, by reading `pretooluse-skill-gate.mjs`, `skill-token.mjs`, `skill-map.mjs`,
   `wire-pretooluse-settings.mjs`, `pretooluse-skill-gate.test.mjs`] The gate's header comment claiming
   PreToolUse "does not fire inside subagents" (dated 2026-06-07) was stale. The audit log entries above
   prove the hook fired for every one of the sub-agent's calls; the gate was not a structural bypass.
   `skill-token.mjs`'s `missingFromTranscript` reads whatever transcript text it is handed; it never
   distinguished parent from sub-agent.
2. [CONFIRMED, by one WebFetch of the Claude Code hooks reference, `code.claude.com/docs/en/hooks`] The
   documented PreToolUse payload fields are `session_id`, `prompt_id`, `transcript_path`, `cwd`,
   `scratchpad_dir`, `permission_mode`, `hook_event_name`, `tool_name`, `tool_input`, `tool_use_id`, plus
   two fields present only inside a sub-agent call: `agent_id` and `agent_type`. The docs state hooks
   fire the same way inside sub-agents and the payload carries `agent_id`/`agent_type` to identify the
   acting sub-agent, but document only one `transcript_path` per session, with no separate sub-agent
   transcript-path field.
3. [CONFIRMED, by listing files under the local machine's Claude projects directory (a `.claude/projects/`
   tree under the invoking user's home, resolved at runtime, not a literal path) matching
   `lane-prepush-check`, names and sizes only, no transcript content printed] Two sampled sessions each had
   a sibling
   `<parent-dir>/<parent-basename-without-ext>/subagents/agent-<agent_id>.jsonl` file distinct from the
   parent's own top-level `.jsonl`. Every line sampled in a sub-agent file carried `"isSidechain":true`
   (89 of 89 in one sample); the parent's own file carried 0 such lines. A sub-agent's `Skill` tool_use
   is written only to its own file, never to the parent's, confirming the brief's hypothesis: a gate that
   always reads `payload.transcript_path` can never see what a sub-agent itself loaded.

**The fix.** New module `fsi-app/.discipline/governance/agent-transcript.mjs`,
`resolveActingTranscriptPath(transcriptPath, agentId)`: no `agentId` returns the payload's own path
unchanged (main-session call, unaffected); an `agentId` derives the sibling sub-agent file per the
layout found in fact 3. Wired into `pretooluse-skill-gate.mjs` at the one place the payload's
`transcript_path` is read, so every downstream check (`gateWrite`, the DEADLOCK ESCAPE unresolvable/
file-read fallbacks) now judges the acting agent's own transcript. Fail-closed is unchanged: a derived
transcript that does not exist still denies with the existing no-transcript tag.

**Comments corrected, dated, citing the evidence above:** the file header COVERAGE block, the
WORKTREE-ISOLATION belt comment, and the dispatch-tools (`Agent`/`Task`/`Workflow`) comment plus its
`ask` message text in `pretooluse-skill-gate.mjs`; the "Coverage limit: subagents and workflows" section
of `fsi-app/.discipline/governance/OUT-OF-REPO-BOUNDARY.md` (the gate's existing runbook section,
extended in place, not duplicated). The dispatch ASK still fires every time; only its claim that a
sub-agent's later calls go ungated was removed, since they do not.

**Tests, attack form:** `agent-transcript.test.mjs` (new, 5 cases including the attack case: the
resolver must never fall back to the unmodified parent path once an `agentId` is given).
`pretooluse-skill-gate.test.mjs` gained 5 cases: a sub-agent payload allowed on its own transcript; the
same payload denied when ONLY the parent transcript holds the load (a skill loaded solely by the parent
does not count for the sub-agent); a sub-agent payload denied fail-closed when its derived transcript
file does not exist; two main-session cases (no `agent_id` field) proving the existing behaviour is
unchanged both ways. All 31 cases in the gate's test file pass; both new test files pass in isolation
(verbatim counts in the report).
