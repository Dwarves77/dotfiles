## 2026-09-19, W9 lane D28b: the UX-compliance check reads the per-lane session-log files

Model: Sonnet. Worktree `/home/user/dotfiles/.worktrees/wt-d2`, branch
`lane/d28b-memory-gate-ux-sessionlogd-2026-09-19`, base `origin/master` `91fd73fb`.

**Result [CONFIRMED by running the real gate script directly, both before and after the fix]**:
`fsi-app/.discipline/governance/memory-gate.mjs`'s `uxGateVerdict` was fed, by the CLI main only,
`docs/ops/session-log.md`'s own diff for the range. D28 (2026-09-13, lane L18) taught
`memoryGateVerdict` to accept a per-lane `docs/ops/session-log.d/YYYY-MM-DD-<slug>.md` file, but the UX
half never learned about it: a lane that touches a `.tsx`/`.css` file and writes its UX compliance
block into its own per-lane file (the D28-mandated shape, since every lane appending to the one shared
`session-log.md` file caused rebase conflicts) was refused at push with "the session-log addendum added
in the same range has no 'UX compliance' block", although the block existed, just in the other file.

Fix: a new pure function `memoryDiffPaths(files)` selects, in order, `docs/ops/session-log.md` (if
present) then every `docs/ops/session-log.d/YYYY-MM-DD-<slug>.md` file in the range (the README and any
malformed name excluded, mirroring `classifyChanged`'s MEMORY bucket). A new live-driver function
`gitMemoryDiffLines(range, files)` runs `git diff <range> -- <path>` for each of those paths and
concatenates the added lines, in that order; the CLI main now hands this combined diff to
`uxGateVerdict` instead of `docs/ops/session-log.md`'s diff alone. No change to CODE/MEMORY/SURFACE
classification, no new allowlist. The refusal message and the header contract now say the addendum can
be either file. The pre-push hook's step 2b hint and `docs/ops/session-log.d/README.md` were updated to
say the same; `docs/inventories/discipline.md`'s memory-gate row was corrected in place (it described
the UX half as reading "the session-log diff", which through 2026-09-18 meant `session-log.md` only).

RED reproduced the real defect on the real gate (a throwaway scratch branch, never pushed: one comment
line in `fsi-app/src/components/shared/PeersDiscussingStrip.tsx`, a UX compliance block written into a
throwaway `docs/ops/session-log.d/2026-09-19-d28b-red.md`, exit 1, "UX compliance gate" failure).
GREEN reproduced the same scratch branch rebased onto this lane's fix commit: exit 0, "UX compliance
gate OK". Both pasted in the dispatch report.
