## 2026-09-22, lane G3: the Rendering guard measures the site's real fonts (RD-80)

What: the rendering guard never loaded Plus Jakarta Sans or Anton. `fullAppCss()` read globals.css and
theme.css only; the fonts are `@fontsource/*` imports in `src/app/layout.tsx`, so no `@font-face` ever
reached a mounted fixture, `document.fonts.size` was 0 on every guard page, and both declared font
stacks resolved to whatever OS font-matching fell back to, a DIFFERENT fallback on CI (Ubuntu) than a
local Windows run. Every text-dependent measurement the guard has ever made (clipping, wrapping,
intersecting elements, hit targets, card heights) was against the wrong typography, on both platforms.

Fixed:

1. Vendored the exact woff2 files the app ships (`fsi-app/.discipline/rendering/fixtures/fonts/`, latin
   subset, weights `layout.tsx` imports only, `Plus Jakarta Sans` 400/500/600/700/800 + `Anton` 400,
   77.2 KB total, each package's LICENSE beside its files, tracked with `.gitattributes`' new `*.woff2
   binary` rule after finding `git add` was silently CRLF-corrupting the files on this Windows checkout).
2. `fontFaceCss()` (`smoke-fixtures.mjs`, the one home) declares `@font-face` rules against them as
   `data:` URIs, not `file://`: a `file://` src is blocked from the guard's opaque-origin
   `page.setContent()` documents (the same restriction `compose-composite.mjs` already documented for
   images), reproduced live as a permanently-`unloaded` face and a `NetworkError` from
   `document.fonts.load()`. Consumed by `fullAppCss()`/`fullAppCssCompiled()` for every existing
   consumer, and directly by `assertFontsReady()`.
3. `assertFontsReady()` (same file) explicitly calls `document.fonts.load()` for every required
   family+weight before awaiting `document.fonts.ready` (a declared face is lazy, it never starts
   loading until something on the page matches it), then confirms a `loaded` `FontFace` is actually
   registered for each spec before trusting `document.fonts.check()`, proven necessary by attack:
   `check()` reads VACUOUSLY TRUE when the FontFaceSet holds zero entries for a family at all, the exact
   shape of the original defect. `run-rendering-guard.mjs` calls it via `page.addStyleTag()` at every
   page it opens (covering the `fixtures.mjs` legacy legs, which never called `fullAppCss()` at all) and
   folds a failure into its own failure list rather than throwing, so one bad fixture cannot hide the
   rest of the tree.
4. Determinism knobs (`deviceScaleFactor: 1, locale: 'en-US', timezoneId: 'UTC', colorScheme: 'light'`)
   on every `browser.newPage()` call, in the harness, not the CI workflow.
5. RD-80 (`invariants.d/RD-80.mjs`) + remediation-discipline category 49 (new section in
   `.claude/skills/remediation-discipline/SKILL.md`, matched verbatim by the invariant's anchor).
   Enforcer: `rd-80-real-fonts.npmtest.mjs`, proven red-then-green by attack (the false-positive
   `check()`-alone shape is reproduced first, then closed) and pins a real, measured glyph width.
6. Measured the tree: `docs/ops/session-log.d/2026-09-22-g3-audit.md` (F51 check 4 refused
   `docs/audits/`, a lane-owned file, as the brief anticipated), 75 failures (all
   layout-guard: L2 34, L9 31, L6 8, L7 2), zero font-resolution failures, byte-identical across two
   consecutive runs. Not fixed in this lane, per the brief; findings for the part lanes that own
   `/settings`, `/watchlist`, `/research`, `/map`, `/profile`, `/admin`.
