## 2026-09-21, lane G2: the local push gate runs what CI's Fitness job runs

What: `fsi-app/.discipline/hooks/pre-push` had no step running `fsi-app/**/*.npmtest.mjs` at all, while
`.github/workflows/discipline.yml`'s required "Fitness functions" job did (the "App unit tests requiring
npm deps" step). PR #769 passed the local gate and failed that CI step. Fixed:

1. `fsi-app/.discipline/hooks/lib/run-npmtest-suites.sh`: one home for the npmtest discovery + command
   (`git ls-files 'fsi-app/**/*.npmtest.mjs'` into `node --test`); both `discipline.yml`'s step and a new
   pre-push step 3e call it. Fails loud, names `npm ci` as the fix, never installs or skips silently, when
   `fsi-app/node_modules` is absent or empty.
2. Pre-push step 3f runs `fsi-app/scripts/verify/run-goldens.mjs` (Behavioral goldens), the job's other
   npm-dependent test step, also unwired locally before this lane, in scope per the brief's own title
   ("the local push gate runs what CI's Fitness job runs" is the whole job, not one step).
3. `F54-push-gate-npm-parity` (RD-79, `fsi-app/.discipline/governance/invariants.d/RD-79.mjs`): reads
   every test-running step of the "Fitness functions" job (name contains test/golden/lint, or its `run:`
   invokes a tracked `.mjs`/`.sh` script) and fails when the pre-push hook does not also call that script,
   unless a dated, reason-bearing `EXEMPT_STEPS` entry applies. Two entries today: actionlint (downloads a
   pinned checksum-verified binary, not a tracked script; operator: "We do not need to install extra
   software use GitHub") and the rendering-guard job's Playwright install (a different job this checker
   does not yet scan, named per the same ruling in case it is later widened). Proven by attack: an extra
   test step the hook lacks fails; the matching pair (hook wired) passes; an exemption entry missing a
   date or a reason fails too. A live test also runs the checker against the real discipline.yml + real
   pre-push and asserts 0 violations (self-consistency: this lane's own wiring must satisfy its own gate).

Coordinator amendment (addressed before completing): CI's exact npmtest command (`git ls-files
'fsi-app/**/*.npmtest.mjs'` into `node --test`, repo root) measured 1430 tests / 1426 pass / 1 skip / 3
FAIL on this Windows PC, all three green on Linux CI. Fixed at the cause, verified red-before/green-after
on this PC, no behaviour change on POSIX:
- `fsi-app/src/components/sources/ProvisionalReviewTable.npmtest.mjs`: a dynamic `import(resolve(...))`
  handed a raw Windows path (`C:\...`) to the ESM loader (`ERR_UNSUPPORTED_ESM_URL_SCHEME`), same class
  as remediation-discipline category 44 (a hand-built path string instead of Node's own URL machinery).
  Fixed with `pathToFileURL(...).href`, the pattern `ImpactMeter.npmtest.mjs` already uses.
- `fsi-app/src/components/ui/SectionRule.coverage.npmtest.mjs`: two assertions compared
  `path.relative()`'s OS-native output (backslash on Windows) against forward-slash literals. Fixed with
  the repo's existing `posix()` normalization (`p.split(sep).join("/")`, the pattern `run-artifact.mjs` /
  `glob.mjs` / the review-apply test helpers already use).
Totals after the fix: 1440 tests / 1439 pass / 1 skip / 0 fail (10 more tests register/pass because the
ProvisionalReviewTable failure used to abort the whole file's `test()` registration at module-load time).
