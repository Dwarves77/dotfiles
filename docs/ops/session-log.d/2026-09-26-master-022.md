## Evidence [CONFIRMED]

`gh run view 36217460080 --log-failed`: rule 022 (`fsi-app/.discipline/rules/022-no-dash-glyphs.mjs`)
FAILed the push check on an added literal em dash in `fsi-app/src/components/ui/Absence.tsx`, in a
rendered value-placeholder span (the "dash"/"narrow" merged variant).

## Root cause of the blind spot [CONFIRMED]

Not a wrong git range, not base staleness, not a rebase/force-push losing a commit. Reproduced with real
`git diff`/`git show` against the repo's own actual history (fork point `98d0032c`/#803, interior commit
`3d30f3feb`, branch tip `aea9f70`, all real PARITY-PARTS commits):

- `git show -U0 <3d30f3feb>` (isolated per-commit diff): **0** added lines contain the glyph. This
  commit merges the old separate "dash" and "narrow" render branches into one, reusing the base file's
  own existing glyph line unchanged for both.
- `git diff -U0 <98d0032c>..<aea9f70>` (ONE cumulative diff over the identical commit range): **1**
  added line contains the glyph.

Same net change, computed two ways, disagree on which line is "new." Cause: the base file
(`Absence.tsx` at the fork point) contains the em-dash literal in TWO places, one raw, one inside an
escaped CSS string (`content: "\\2014"`). A duplicate literal gives git's diff/Myers-LCS algorithm more
than one equally minimal alignment. A per-commit walk sees each change's own small neighbourhood and
picks one alignment; a single whole-range diff sees the full accumulated change and is free to pick a
different one, pairing the base's one raw occurrence against a DIFFERENT surviving line than the
per-commit walk did, and reporting the CSS block's replacement as a fresh addition instead. This is a
general property of text diffing, not a defect specific to this file.

The push-to-master check runs the discipline engine against ONE commit (the squash) vs its real parent,
i.e. exactly one cumulative diff over the whole net change. The PR's pull_request check
(`runner.mjs --mode=ci --range=...`) iterated `git log`'s commit list and ran `buildContextForExistingCommit`
**per commit**, unioning each commit's own isolated "added lines." That union is what missed the glyph:
no single commit's own isolated diff ever showed it as added, even though the total range's cumulative
diff does. The two paths were never diffing the same thing.

## Fix

`fsi-app/.discipline/lib/context.mjs`: new `buildContextForRange({ range })` builds a context from ONE
`git diff <range>` (not `git log` + per-commit `git show`), mirroring exactly what a squash merge will
land. `getAddedLines` gained a `range` diffSource branch.

`fsi-app/.discipline/runner.mjs`: the `--mode=ci --range=` path keeps its existing per-commit loop
UNCHANGED (commit-message rules, revert/merge-commit trigger gates keep their per-commit granularity)
and ADDS a second pass, the same range run once as a whole-range context, worst exit code wins. This is
additive, not a replacement; no existing rule's per-commit semantics changed.

Verified against the real historical range: `node .discipline/runner.mjs --mode=ci --range=98d0032c..aea9f70`
now FAILs rule 022 on the exact offending line, where the pre-fix per-commit-only loop passed it.

`fsi-app/src/components/ui/Absence.tsx`: the glyph line now reads as the JS escape form (byte-identical
render), matching existing repo practice for a rendered dash placeholder
(`MarketComparativeRibbon.tsx`'s narrow-absence dash, `timeline-parse.mjs`'s date-range separator).
Rendering is unchanged; nothing else in the component moved.
