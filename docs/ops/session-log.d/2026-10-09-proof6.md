# 2026-10-09, lane PROOF-6 (proof6-chain-proof-oracle-role): the chain proof's schema oracle is a second cluster, applied as the superuser with ON_ERROR_STOP=1

Defect: chain-proof run 37876624407 replayed 343 of 343 migrations and then failed at the oracle step: the production schema dump was applied to a scratch database (oracle_check) as the stack's ordinary `postgres` role, 2738 fatal errors, the first two being "can only create extension in database postgres" (dump line 16) and "must be owner of schema public" (line 23). The first executor brief said to apply as the `postgres` superuser to database `postgres`; the lane stopped and reported that this was not implementable as written (the `postgres` role is not a superuser, `supabase_admin` is; the replay owns the stack's `postgres` database). Coordinator ruling 2026-10-09: Option A in its lightest form, a second cluster.

## Accomplished

1. `.github/workflows/chain-proof.yml` (oracle steps only): the "Create the empty oracle_check database" step is now "Start the oracle cluster" (`create-oracle-db.mjs`, still before the replay); the apply step is "Apply the production schema dump to the oracle cluster" (`--db-url "$PROOF_ORACLE_DB_URL"`); the final step runs `docker rm -f chain-proof-oracle`. Header comment states the why and that no role or ownership statement is rewritten or stripped.
2. `fsi-app/scripts/proof/create-oracle-db.mjs`: reduced to the container start. Reads the stack's database image from `docker ps --filter name=supabase_db_` (no tag typed), runs it detached as `chain-proof-oracle` on `127.0.0.1:54399`, password from the stack's own `PROOF_DB_URL`, then waits until `pg_roles` holds all five roles the dump names (postgres, anon, authenticated, service_role, supabase_admin). The template-clone, terminate-sessions, drop and create-database path is deleted.
3. `fsi-app/scripts/proof/write-local-env.mjs`: `PROOF_ORACLE_DB_URL` = the stack's URL with role `supabase_admin`, port `ORACLE_PORT` (54399), database `postgres`. `PROOF_DB_SUPERUSER_URL` is removed (its only consumer was the old create step).
4. `fsi-app/scripts/proof/apply-schema-dump.mjs`: `psql -v ON_ERROR_STOP=1 -f <the dump itself>`. `stripOwnership`, `classifyErrors` and the non-fatal role handling are deleted. A psql that exits non-zero without an ERROR line (refused connection) is red. `assertOracleUrl` refuses a URL that is not loopback, not `supabase_admin`, not database `postgres`, or on the stack's own port; the CLI no longer falls back to `PROOF_DB_URL` or `SUPABASE_DB_URL`. The report keeps `fatal_errors`, `role_errors`, `public_tables` (read by `emit-chain-proof-artifact.mjs`); `ownership_statements_dropped` is gone.
5. Tests: `chain-proof-workflow.test.mjs` (oracle contract checkers over the workflow text, the written env and the script source, each with a control and mutation attacks), `apply-schema-dump.test.mjs`, `create-oracle-db.test.mjs`, `write-local-env.test.mjs` rewritten for the new shape. `schema-diff.mjs` needed no change: it already takes `--replayed` and `--oracle` URLs.
