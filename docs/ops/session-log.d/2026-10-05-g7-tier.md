# 2026-10-05 lane G7-TIER: every automatic tier writer respects the tier override, proven by attack

## Accomplished
- Enumerated every code path that writes sources.base_tier, effective_tier or tier_override (git grep of writes across src, scripts, supabase/migrations; `from("sources")` update/upsert, guardedUpdate/guardedUpdateByIds on sources, raw SQL). Table below.
- One shared guard, `fsi-app/src/lib/sources/tier-override-guard.mjs` (`notUnderTierOverride`, `withTierOverrideGuard`, `writeEffectiveTierUnlessOverridden`): `tier_override IS NULL` in the UPDATE statement itself. Used by four writers (source-growth, recompute-tiers, institution-canonicalize, resolve-provisional-sources) and by commit-tier-change.
- `applyTierMovements` (trust.ts) now takes a writer result `{ written: false }` as an override skip: counted in `override_skipped`, not counted as applied, no tier_promotion/tier_demotion event (before, a refused write still recorded an event for a move that never happened).
- commit-tier-change refuses a source with a tier_override: 409 naming the override and `/api/admin/sources/<id>/tier-override`; the UPDATE carries the guard too, so an override set after the read is also refused. Decision and write moved to sibling `logic.ts` (route files export only handlers, F34). Audit behaviour unchanged (console line and d3AuditEvent on success only).
- Attack tests (rule 15): `scripts/maintenance/tier-override-attack.npmtest.mjs` (10 tests, a control and an attack per writer) and `src/app/api/admin/sources/commit-tier-change/route.npmtest.mjs` (4 tests). The fake store applies the statement's own filters, and the admin override is set after the writer's read and before its UPDATE. Both run by the `**/*.npmtest.mjs` glob in discipline.yml.
