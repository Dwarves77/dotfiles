# 2026-10-09, lane CI-FIX-1 (cifix1-docs-only-and-required-checks): a docs file a test or gate reads is never docs-only, and the required check names are pinned

Register cells (RULES-X-1, items 10 and 11): the docs-only fast path classed an edit to a docs file that a test reads (OUT-OF-REPO-BOUNDARY.md, the design AUDIT-2026-09-07.md) as docs-only, so the suite that reads it was skipped; and the required-check job names were not pinned anywhere, so a renamed job dropped out of branch protection silently.

## Accomplished

1. `fsi-app/.discipline/governance/docs-only-range.mjs`: new exports `extractReadDocPaths(sources)` (PURE) and `loadReadDocPaths(repoRoot)`. The list of read docs is DERIVED at run time by scanning the tracked `fsi-app/**/*.test.mjs`, `*.npmtest.mjs` and every `.mjs` under `fsi-app/.discipline/` for docs-like paths (`.md`, `.json`, `.txt`) on a read, exists, resolve or join line, named path constants, and `join()`/`resolve()` of segments; comment lines and plain lists of names are skipped; the module's own files are excluded. `isGoverningDocPath`, `isDocsOnlyPath` and `isDocsOnlyDiff` take an optional read-docs set (default: the scan of the current repo); the CLI scans the repo it runs in and exits 2 if the scan fails. [CONFIRMED: node --test, 30 pass with rename-source-class.test.mjs]
