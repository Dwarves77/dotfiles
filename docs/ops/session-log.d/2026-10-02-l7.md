## Correction recorded (brief-l7.md got the mint-site file wrong)

The brief's READ FIRST item 1 and its "exact write set" both name `canonical-pipeline.ts` as the mint
chokepoint to reuse. That file is the BRIEF-GENERATION pipeline (`groundBrief`/`sectionBrief`/
`generateBrief`), not the mint site. The real "ONE sanctioned INSERT site" for `intelligence_items` is
`src/lib/intake/mint-item.ts`'s `mintIntelligenceItem` (confirmed by reading that file's own header and
the function itself: "THE single INSERT ... the only intelligence_items INSERT in src/ runtime"). This
lane reuses `mint-item.ts`, never `canonical-pipeline.ts`. Recorded in `research-walker.mjs`'s own header
comment as well, per rule 13's corollary (a flag that dissolves under evidence gets a same-session
correction wherever it was recorded).

A second, self-caught correction: the first draft of `buildFixtureSbClient`'s `.in()`/`.limit()`
implementation ignored the queried URL list and returned the ENTIRE `registeredSources` array for every
`sources` table read, regardless of which host was being checked. That silently let every OpenAlex
candidate match the FIRST registered grey-lit source (a hollow pass of the source-link invariant this
file exists to exercise honestly) -- caught by running the real CLI and seeing `would_mint:5` where only
3 sources were registered. Fixed to filter `registeredSources` by the queried `.in()` values before the
fix landed in any commit; re-ran both required dispatch runs afterward (the artifacts above are
post-fix).
