## Task 4: composer 400 without entity_ids

Investigated the brief's literal premise ("a post without entity_ids is valid per R8.7") against spec
07's own amendment text, which states items 2-6 (entity binding is item 2) "stay unchanged". **[REFUTED]**:
no defect found where a well-formed `entity_ids` array 400s; both client (`api-client.ts`,
`identity-format.ts`) and server (`posts/route.ts`) required a non-empty array, consistently, before
this lane touched anything. Did NOT remove the requirement (would violate spec 07 section 5 component
2 / acceptance criterion 6 and migration 293's `community_thread_entities` cardinality rule). Found and
fixed the real, narrower, adjacent defect: the client-side check only verified non-empty, not the
malformed-id or `MAX_ENTITY_IDS` (10) rules the server also enforced, a class-drift risk (Postel's Law,
UX law 14: explain requirements before submission), not today's live bug but a real one bad data could
have hit. Fixed by extracting one shared `validateEntityIds` (`entity-binding.mjs`), imported by both
sides; `route.ts`'s three separate inline checks collapsed into one call.
