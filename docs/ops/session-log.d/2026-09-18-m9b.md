## 2026-09-18, W9 lane m9b: harness truth (dispatch ledger, maintenance artifacts, closure-gate perf)

Lane m9b (stage-audit-2026-09-18 s6-gates-harness.md, section 6.1 row M9, the harness half). Three
mechanisms that record whether things ran were themselves not running: the dispatch ledger
(docs/ops/dispatch-ledger.jsonl) stopped at 2026-09-07 while 24 maintenance steps landed since, because a
person appended it by hand; maintenance.yml uploaded an ephemeral artifact instead of committing one, so
this family had no scripts/harness-runs/ history; closure-gate.mjs no longer finished inside a short
wall-clock budget (two prior audit attempts timed out).

**What landed.** (1) `scripts/harness-runs/append-dispatch-ledger.mjs`, a pure row builder plus a
file-append, unit-tested (7 tests): the exact 7-field shape the existing 81 hand-written rows carry (date,
workflow, step, mode, run_id, outcome, note); an artifact path folds into `note` as free text rather than a
new field, matching how the existing rows already reference an artifact. Wired as maintenance.yml's own
final steps, which compute outcome from the job's own status and commit the row alongside the new harness
artifact via the same branch-plus-PR mechanism source-sweep.yml already uses
(scripts/turns/deliver-artifact-branch.sh, copied, not reimplemented). A single marker row records the
2026-09-07 to 2026-09-17 gap this lane deliberately did not backfill, per the brief. (2) The `maintenance`
harness family registered in ALLOWED_FAMILIES (scripts/lib/run-artifact.mjs), GOVERNING_FILES
(scripts/harness-runs/governing-files.mjs: `../.github/workflows/maintenance.yml` plus
`scripts/maintenance/lib/cli.mjs`) and CONVENTION.md's table, directory layout, family prose and standing
metric; `scripts/maintenance/write-run-artifact.mjs` (11 tests) writes and commits
`scripts/harness-runs/maintenance/maintenance-run-NNN.json` plus a `traces/` full-trace companion
consolidating every step's own summary.json, in addition to the existing upload-artifact step, not instead
of it; `scripts/harness-runs/maintenance/PENDING-RUN.md` is the family's first-run marker (F28 rule (b)).
(3) `.discipline/governance/closure-gate.mjs`'s `gatherNeverRunTargets` used to spawn one
`git merge-base --is-ancestor` per (target, train) pair and one `git log -S<literal>` pickaxe search per
maintenance step (62 spawns against the same file). Measured, not assumed: one merge-base call ~215ms, one
pickaxe call ~349ms, 59 trains, 62 steps. Fixed at the cause: `trainOf` now binary-searches the ascending
(monotonic, by construction) train list and memoizes by commit hash within a run; the 62 pickaxe searches
and the ~19 per-other-workflow file-introduction searches are each replaced by one batched `git log -p` /
`git log --diff-filter=A --name-only` scan, parsed in memory, instead of one spawn per target. The gate's
checks and allowlists are unchanged. Measured before and after, same tree: the LIVE NEVER-RUN test alone
went from over 90 seconds (two prior attempts, did not finish) to about 8 seconds; the full
closure-gate.test.mjs (34 tests) now completes in about 11 seconds.
