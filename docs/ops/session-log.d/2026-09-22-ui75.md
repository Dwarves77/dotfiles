### Causes found (parts, not pages)

1. **L6, 8 findings, `/watchlist`.** `NoticeRow` in
   `fsi-app/src/components/figures/RecalculationNotice.tsx` built its own `<li className="cl-row-card">`
   shell instead of rendering through `SectionCard`, so it never mounted `<SectionRule/>` (the part that
   owns the 3px top rule, F42). Fix: `SectionCard` gained an `as="li"` option
   (`fsi-app/src/components/ui/SectionCard.tsx`) and `NoticeRow` now renders through it
   (`fsi-app/src/components/figures/RecalculationNotice.tsx:52,90`). Renders on `/watchlist` (the
   Recalculation notices card) and every other `NoticesRail`/`RecalculationNotice` call site
   (`/market`, all four detail routes), one part, every call site fixed.

2. **L7, 2 findings, `/admin`.** `WorkspacesUsageRow`'s "Newest join" tile
   (`fsi-app/src/components/admin/redesign/WorkspacesUsageRow.tsx:161-176`) rendered a join DATE in the
   Anton display face. A date is not a count or numeral and is not in the operator's Anton allowlist
   (page-title, card-title, band-tile-numeral, stat-block-numeral, headline-figure, timeline-callout,
   matrix-cell-score, matrix-fact-figure, nav-wordmark); the allowlist is never grown to fit a finding.
   Fix: that one element renders in the body face (`var(--font-sans)`) instead, same size/weight
   treatment as the tile's other figures.

3. **L9, 7 findings, `/research` (4), `/map` (2), `/profile` (1).** Real font metrics landed several
   hit targets a fraction of a pixel under the operator's 44×28 floor:
   - `ListSurfaceSortRow`'s Window options ("30d"/"90d" on `/research`, also the Sort options on
     `/market`/`/regulations`): `fsi-app/src/components/list-surface/ListSurfaceSortRow.tsx:134-160`.
     First attempt used the padding+negative-margin expanded-hit-area pattern with the visible pill
     moved to an inner span; it cleared L9 but eroded the row's own `gap:10` between adjacent options
     to ~6px, dropping the mobile UX-smoke adjacent-clearance check (`research-rows`/`market-rows`/
     `regulations-ledger` specs, caught by re-running the guard, not assumed). Corrected to a 1px-per-
     side padding increase (10px to 11px) with no negative margin, which clears the floor without
     touching the gap. Session-log corollary of the brief's own "prove by measurement" rule: the correction was
     caught by re-running the real guard after the first fix, per rule 3.
   - `FilterChip`'s "Rail" mode chip on `/map`: `fsi-app/src/components/ui/Chips.tsx:296-317`. This
     component's mobile media query re-styles `.cl-filter-chip` by class selector and does not touch
     padding, so the split-element hit-slop pattern is not safe here without also rewriting that
     selector coupling (verified by reading `FILTER_GROUP_MOBILE_CSS`); a 1px-per-side padding increase
     (11px → 12px) clears the floor at every measured width instead.
   - The three Quick-links rail links on `/profile` (a single 12.5px text line is ~18.8px tall, under
     the 28px floor): `fsi-app/src/components/profile/UserProfilePage.tsx:522-540`. Fixed with the
     padding + equal negative margin hit-area pattern (safe here: the links are a `flex-direction:
     column` stack with `gap:6`, no adjacent-clearance interaction), so the click target grows without
     widening or heightening what the reader sees.
   - The Briefing-day segments ("Tue"/"Thu") on `/settings`, part of this same L9 bucket by rule but
     owned by the `/settings` cause below: `fsi-app/src/components/account/AccountPrimitives.tsx:227-247`
     (`SegmentedControl`). A per-segment `minWidth: 44` widens only the genuinely narrow labels
     (Mon/Tue/Wed/Thu/Fri) rather than repeating a blanket-padding increase, which this same component's
     own comment records already regressed an unrelated "Alert bands" column once.

4. **`/settings`, 54 of the 58 reported findings (L2 34, L9 20): STOP, detector defect, not a page
   defect (brief rule 2).** `[CONFIRMED by direct measurement, see below]` Every one of these findings
   names a `button[<jurisdiction label>]` (Central America, EU, Germany, Greece, and so on, all 87
   entries of `JURISDICTIONS` in `fsi-app/src/lib/constants.ts`) intersecting or overlapping a genuinely
   visible element below it in the page (`DataAndSupersessionsRailCard`, the "Saved searches" section,
   the Archive/Data-summary links). The jurisdiction chips are `BriefingScheduleSection`'s "Jurisdiction
   weighting" `<details>` (`fsi-app/src/components/settings/BriefingScheduleSection.tsx:233-258`),
   closed by default, no `open` attribute anywhere in that file, never programmatically opened.

   A standalone Playwright probe against the real `compose-settings` mount confirms the `<details>`
   element reports `open: false` while the "Central America" button inside it still returns a real,
   non-zero `getBoundingClientRect()` (x:1117, y:811.7, w:109.2, h:28.5 at 1440, the exact box the
   layout-guard's L2 finding cites): `details:not([open])` content in Chromium renders via
   `content-visibility: hidden` (a real layout box, nothing painted, not hit-testable), not
   `display:none` (a zero-size box). The layout guard's `visible()` helper
   (`fsi-app/.discipline/rendering/layout-guard/collect.mjs:25-29`) checks
   `visibility:hidden`/`display:none`/`opacity:0` and a non-zero rect. It does not check
   `content-visibility` or closed-`<details>` ancestry, so it treats this geometrically-laid-out-but-
   invisible-to-the-reader content as "visible content" and flags it against real content below.

   Per the brief's rule 2 ("Never edit the guard... If a finding looks like a detector defect... STOP
   with the element and the measurement"): not fixed. `SettingsPage.tsx`/`BriefingScheduleSection.tsx`
   are not broken; the jurisdiction-weighting disclosure is correctly closed and invisible to every reader
   who has not clicked it. The 4 real findings in this same L9 bucket (Tue/Thu, item 3 above) were
   fixed; the other 54 are this one detector gap, reported for the guard's own owning lane to decide
   whether/how to make `visible()` `content-visibility`-aware.

### UX compliance

- **`/watchlist` Recalculation notices card (and every other `RecalculationNotice` mount).** Primary
  goal: see which figures the reader may have already acted on have since changed. Path: land on the
  page, read the card, no interaction required to see the state. Primary action: the entity link (when
  present) to the changed record. Feedback: none needed (read-only list); no async action on this part.
- **`/admin` Workspaces-usage "Newest join" tile.** Primary goal: see the most recent workspace join at
  a glance. Path: land on `/admin`, read the tile. Primary action: none (display-only). Feedback: n/a
  (no interaction).
- **`/research`, `/market`, `/regulations` Window/Sort row.** Primary goal: change the active sort/window
  without losing place in the list. Path: click one segmented option. Primary action: the active option
  (visually filled). Feedback: immediate (the fill moves synchronously, no network round trip for the
  window toggle itself).
- **`/map` mode filter chip.** Primary goal: narrow the map to one transport mode. Path: click a chip.
  Primary action: the active chip. Feedback: immediate visual state change.
- **`/profile` Quick links.** Primary goal: jump to Dashboard/Settings/Watchlist. Path: click a link.
  Primary action: whichever link the reader wants; all three equally weighted, matching the artboard.
  Feedback: standard navigation.
- **`/settings` Briefing-day segments.** Primary goal: pick which weekday the briefing sends on. Path:
  click one segment. Primary action: the selected day (filled). Feedback: immediate fill; the Save
  button enables once the form is dirty.

No new component was added; every change is a part-level fix to an existing shared component or a
single-element style correction, so no new UX smoke spec registration applies.
