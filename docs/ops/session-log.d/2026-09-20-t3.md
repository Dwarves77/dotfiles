### Amendment 1 and 2 (coordinator, same day): glob-portability.test.mjs brought into this lane's write set

Amendment 1 clarified that "glob-portability... NOT yours" referred to a different, unrelated finding
about that file's NOTES, not the file itself; my change removed the text it parses, so the file is in
scope. Amendment 2 answered a second STOP raised while doing that work (below). Net result: three
latent defects in the OLD mechanism, all closed or exposed by switching to discovery-by-construction, not
introduced by it.

1. **Bare selftest names invisible** [CONFIRMED]. `testGlobFromSuite()`'s regex
   (`/fsi-app\/[^\s"'\\]+/g`, filtered to tokens ending `.test.mjs` or containing `*`) never matched the
   two named `src/lib/sources/` selftests (`classify-source-role.selftest.mjs`,
   `instrument-identity.selftest.mjs`): they carry no wildcard and don't end in `.test.mjs`. Verified by
   running the exact old regex against the pre-lane-T3 committed `run-test-suite.sh`: 80 tokens, neither
   filename present. glob-portability's own portability check silently never ran on those two files for
   as long as that mechanism existed. Closed by construction: `discoverTests()` returns them as ordinary
   members of its set.
2. **Nested-directory globs invisible** [CONFIRMED]. `expand()`'s single-level assumption
   (`dir/*.test.mjs`, split on the last `/`) could not handle the OLD suite's own
   `fsi-app/scripts/producers/*/*.test.mjs` token (a wildcard in the directory segment, not just the
   filename): `dir` resolved to a literal path containing `*`, `readdirSync` threw, the catch returned
   `[]`. Every file under `scripts/producers/<subdir>/*.test.mjs` was invisible to glob-portability's
   checks. Verified by tracing `expand()`'s logic against that exact token. Closed by construction:
   `discoverTests()` discovers `*.test.mjs` at full generality, any depth, no per-directory glob to miss.
3. **Prose read as an import** [CONFIRMED]. Discovering `scripts/producers/regional/` for the first time
   (defect 2, above) surfaced `run-envelope-producer.test.mjs`, which false-tripped
   `nonPortableSpecifiers`'s unanchored `/\bfrom\s+["']([^"']+)["']/g`: a test-name string reading
   "...is counted separately from 'authored'" matches the same shape as `import x from "authored"`. The
   file itself runs clean standalone (19/19 tests pass) confirming this was a detector defect, not a real
   non-portable import. Root-caused per coordinator amendment 2 (option a, fix at the cause): the `from`
   regex is now anchored to a statement start with `import`/`export` (multi-line capable, stops at `;`/
   quote/backtick so it cannot cross into an unrelated later `from`). The other two `MODULE_RES` forms
   (side-effect `import "x"`, dynamic `import("x")`/`require("x")`) are UNCHANGED in behaviour, per
   instruction; five new attack tests added beside `nonPortableSpecifiers`: the exact false positive
   (now clean), single-line `import x from "pkg"`, multi-line `import {...} from "pkg"`,
   `export {...} from "pkg"`, and relative/`node:`/side-effect/dynamic forms all still passing. Re-running
   the full discipline-suite portability check against the real tree after the fix found no other file
   newly failing (the "TRANSITIVE" test also passed clean; no STOP needed here).

`glob-portability.test.mjs` also gained the anti-regression assertion Amendment 1 asked for:
`findInlineTestGlobTokens()` asserts `run-test-suite.sh` contains no shell-expanded `*.test.mjs`/
`*.selftest.mjs` glob token (the exact hazard removed: the file list silently differing, or collapsing to
zero, depending on which shell expands an unquoted glob), with its own attack test proving a fixture
string containing such a token fails it and a clean fixture passes.
