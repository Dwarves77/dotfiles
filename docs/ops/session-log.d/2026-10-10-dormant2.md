## 2026-10-10, lane DORMANT-2 (dormant2-disabled-with-old-run): the closure gate's disabled-workflow excuse, re-diagnosed; live-run lookup and failure output hardened

Brief premise: a workflow GitHub reports as disabled, whose newest live run is older than the window, FAILED the NEVER-RUN check while the same workflow with no run passed (PR 1088, Discipline engine run 38048818939, test "GATE-9 exit status: closure-gate.mjs exits 0 on the committed tree").

### Accomplished

1. Re-diagnosed the premise against the logs and the code (findings below). The disabled-with-old-run case is already excused by master's code; the premise as written is not what the log shows.
2. `fsi-app/.discipline/governance/closure-gate.mjs`: `liveRunEvidence` now returns the newest EXECUTED run among the workflow's newest `LIVE_RUN_PAGE` (20) runs instead of inspecting only the single newest run; `fetchLiveRun` asks `runs?per_page=20`. A queued, cancelled or skipped newest run no longer hides an executed older run.
3. Same file: new pure `describeFailures`, used by the CLI, so a red gate names each failing target and allowlist issue in its default output (it printed only `1 FAILING` without `--report`).
4. `closure-gate.test.mjs`: seven new DORMANT-2 tests (the four requested cases, an end to end gatherer case, the run-page case, the describeFailures case) and the `per_page` assertion updated.

### Decisions

- The excuse logic is left as it is: it already excuses a `disabled*` state whatever the age of the newest executed run, and the note still reports the age.
- Only the newest EXECUTED run in a 20-run page is used as evidence: a pull_request workflow receives a queued or concurrency-cancelled run on every push, which the single-run lookup read as no evidence.
