## Decisions

1. [CONFIRMED by parse] The live set is 22 policies, not 23: `post_promotions_select` (041, repointed by 182) is excluded because migration 348 dropped the table. The test proves the exclusion (the parse sees the CREATE and the DROP TABLE).
2. [CONFIRMED by reading] 027 (user_profiles), the 032 and 041 originals, and the 043 and 048 originals are superseded by later DROP POLICY plus CREATE POLICY; the parse applies them in order and the final set equals the 22.
3. The predicate is written `(SELECT public.is_platform_admin())` in every policy for the InitPlan cost; the catalog assertion strips the deparser's `AS is_platform_admin` alias so the form passes while any column reference fails.
4. The readers' error policy differs by purpose: the route gate and the Community shell fail closed (error means not admin); the identity bootstrap throws, because its bit feeds the nav and an unknown answer must not read as "not an admin" (same stance as the AUTH-IDENTITY errors it already throws).
5. `admin.ts isPlatformAdmin(userId, client)` is not moved to the rpc: it takes an arbitrary userId, which the no-argument predicate cannot answer, and its callers (moderation reports route, coverage entries, org members, workspace bootstrap) already pass the service client.
