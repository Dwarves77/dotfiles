## What this lane reaches, and what it does not (stated plainly per the brief)

`system-prompt.ts` and `metadata-vocab.ts` are the ONLY files this lane's write set permits, and
neither is on the path that assembles the model's actual input context for a run (that is
`canonical-pipeline.ts`, the mint chokepoint, named off-limits in the brief). **[CONFIRMED by grep,
2026-10-02]:** `fsi-app/src/lib/agent/canonical-pipeline.ts` and `fsi-app/src/workflows/generate-
brief.ts` contain NO reference to `research_assessments`, `read-assessments.mjs`,
`planning_assumption_register`, or `assumptions/read.ts`. Neither table's real rows reach the model's
input context today. So as of this run:

- The PROMPT now requires the field, names the real columns on both tables, and forbids inventing a
  value - this is live and tested.
- A LIVE regeneration today would, correctly per this prompt, fall through to the absence sentinel
  every time (no real assessment or assumption data is in its input), which is spec-03S1-compliant
  (never blank, never invented) but is not yet "wired to the assessment model" in the data-flow sense
  the lane's title implies.
- Wiring the actual table reads into the model's context is a `canonical-pipeline.ts` change - a
  different write path, explicitly this lane's L7/mint-chokepoint boundary, not L9's.
