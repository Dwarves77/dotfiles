## Root cause [CONFIRMED]

CI's "Discipline engine unit tests" job and pre-push step 3 run the SAME script,
`fsi-app/.discipline/run-test-suite.sh`, so script-path parity (what F54 checked) held. The
**environment** did not. CI's job never runs `npm ci`: no npm package can resolve there. Locally one
always resolves: the main checkout's own `fsi-app/node_modules`, or a linked worktree's shared link
(`worktree-node-modules.sh`, RD-85). The suite's contract, "every discovered test imports only `node:`
builtins + relative files; npm-dependent tests are named `*.npmtest.mjs`", was enforced by the filename
suffix alone (`test-discovery.mjs`). `plan-quarantine-disposition.test.mjs` (a `.test.mjs`) reached
`buildHarnessRunsClient()`'s `await import("@supabase/supabase-js")`: resolved locally, "Cannot find
package" in CI. Env parity was also absent (main checkout has `fsi-app/.env.local`; CI has no creds);
**not** a cause of these runs (they were pushed from a worktree with no env file, shell carries no
credential vars) but the same class, closed in the same fix.

The instance itself was already fixed at d8c63c8f (the test moved to
`plan-quarantine-disposition-write-client.npmtest.mjs`). This lane fixes the class.

## The fix (commit on lane/ci-parity)

1. `fsi-app/.discipline/lib/no-npm-sandbox.mjs` (new), loaded by `run-test-suite.sh` via
   `node --import`: refuses any package from an install the checkout reaches, for CJS
   (`Module._nodeModulePaths` filtered) and ESM (a `node:module` resolve hook, CI's own error text), and
   also blocks the realpath of that install (Node's ESM resolver realpaths through the shared junction).
   A `node_modules` elsewhere (a test's fixture under `os.tmpdir()`) is untouched, as in CI.
2. `run-test-suite.sh`: unsets `env-file.mjs`'s `CREDENTIAL_VARS` (read from that module, not copied)
   and sets `FSI_NO_ENV_FILE=1`. No-ops in CI.
3. F54 widened from one job to every `discipline.yml` job that can fail the workflow (a job-level
   `continue-on-error: true` job is skipped by that rule, not a list), plus new assertions that the
   no-npm suite runs under the sandbox with the env switch and credential unset, and that the CI job
   running it installs no npm packages. 10 new tests, attack-shaped (rule 15).
4. Widening F54 found four CI steps the push gate never ran; wired as pre-push step 2c
   (`runner.mjs --mode=ci --range=origin/master..HEAD`; commit-msg runs a different rule mode) and 3g
   (`closure-gate.mjs`, `skill-contract-map.mjs --check`). `orphan-modules.mjs --all` is a report that
   never fails: dated EXEMPT_STEPS entry. About 40 s added.
5. pre-push step 3's failure output printed `tail -40`, the LAST xargs batch's summary, all green when
   the failure sat in an earlier batch; it now prints every batch's failing-test blocks.
6. F25 Source 11: `.sh` scripts a workflow or hook invokes are followed for `.mjs` roots (fixed point).
   Without it the sandbox read as an unwired module, and test-discovery.mjs was only wired by accident.
7. RD-79's text corrected in place (it described F54 as Fitness-job-only); `no-npm-sandbox.test.mjs`
   added to its `enforcedBy`.
