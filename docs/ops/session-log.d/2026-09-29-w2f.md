## Class 1: the "16-instrument classifier"

**Question the code answers:** which `binding_position` (direct duty / carrier pass-through / customer
contract / monitoring) does a regulatory item have, for any instrument spec-01 section 1 names.

**Finding [CONFIRMED read]:** the brief (and `docs/plans/wave2b-lanes-2026-09-29.md`'s write-set table)
both name `src/lib/classification/classify-source.mjs`. That file has no instrument concept at all , it
is Axis 3/4/5 source classification (jurisdiction/topic/mode/vertical), never an instrument list. The
real "16-instrument classifier" the intent-vs-live audit names is
`fsi-app/src/lib/obligations/classify-binding-position.mjs` (confirmed against
`docs/archive/logs/intent-vs-live-and-competition-2026-09-24.md:36,48,163`, which states verbatim:
"`classify-binding-position.mjs:36-122` is those 16 regexes and nothing else").

**Mechanism:** true generalisation beyond the 16 named spec-01 instruments needs a profile-attribute-
driven applicability model (already tracked as its own P0 in that audit, section "Missing code"). That
is a separate, larger build, not a coverage fix, and building it here would either fabricate a legal
mapping for instruments spec-01 never analysed (rule 2) or duplicate the tracked P0 work. What WAS a
real, fixable class gap: only about 8 of the 16 rules had any test exercising them at all (rule 15 ,
before this change, a rule's regex could silently stop matching its own instrument and nothing would
fail). Added a `label` field per rule (verbatim from its own citation) and a coverage test
(`classify-binding-position.test.mjs`) that iterates `BINDING_POSITION_RULES` itself and asserts every
rule classifies its own label correctly , so a 17th instrument added to the table is automatically
covered, and the test never hand-copies a second instrument-name list that can go stale against the
first.

**Test:** `fsi-app/src/lib/obligations/classify-binding-position.test.mjs`, two new tests: "class
coverage: every RULES entry classifies its own label" (16/16, was ~8/16) and "class coverage: two
distinct real carrier_passthrough instruments" (CORSIA, ReFuelEU Aviation , both real spec-01 rows).
14/14 tests pass.

**WRITE-SET:** expanded by coordinator ruling (2026-09-29) to include
`fsi-app/src/lib/obligations/classify-binding-position.mjs` (+test), resolving the mismatch between
W2-F's original write set (`src/lib/classification/**`) and this class's real file.
