## 4. The flywheel

### 4.1 It is two mechanisms. Do not conflate them.

**Loop A — discovery compounding** `[CONFIRMED]` `docs/plans/recursive-compounding-discovery-2026-08-10.md`. Corpus grows → grounded edges cluster into themes → cluster *shape* exposes a gap → the gap becomes a discovery target → finding it adds nodes → re-cluster. Four feedback edges: **L1** incremental discovery at mint · **L2** cluster → gap → scan target, the compounding core · **L3** trajectory → anticipatory discovery · **L4** recurring `basis` patterns proposed as new scorer signals.

Well-foundedness rests on four named properties: deterministic fixpoint, grounded-or-not-emitted edges so error cannot enter the loop, bounded edge growth (threshold 0.3, limit 12, `[CONFIRMED]` `fsi-app/src/lib/connections/discover.mjs:93`), and a loop-until-dry base case.

**Loop B — decision propagation** `[CONFIRMED]` `docs/specs/08-flywheel-design.md` §2. A fact changes → transactional outbox row → invalidation DAG marks the transitive closure stale → a *governed* drain recomputes → the reader is told which of their decisions moved. **Deliberately not armed:** no cron, no `pg_cron`, no queue. The drain is an operator action.

**Loop B is DESIGNED ONLY.** No migration defines `entities`, `entity_identifiers`, `propagation_events`, `derivation_edges`, `statutory_computations`, `estimated_values`, or `sensitive_field_policy`. `[CONFIRMED]` — grep over `fsi-app/supabase/migrations/` returns nothing.

**On the human question, stated precisely.** There is no human reviewing or approving edges or themes; those are deterministic. There is an **operator** step: L2 gaps are written as `integrity_flags` of category `coverage_gap` for operator triage, and L4 is gated, surfaced for ratification, and never self-modifies the scoring source of truth. `[CONFIRMED]` `analyze-corpus.mjs` header. **No customer-entered data enters the loop** — `analyze-corpus.mjs` reads only `intelligence_items` where `provenance_status='verified' AND is_archived=false`, and `admissibleFor()` refuses `community` origin for calculation or filing with no override. `[CONFIRMED]`

### 4.3 The flywheel's cost model

**$0, no model call:** L1 discovery, all clustering, centrality, convergence, trajectory, and L2 gap detection. `analyze-corpus.mjs` states it in its own header: "$0: no LLM, no paid fetch." `[CONFIRMED]`

**Metered:** F5 theme-brief synthesis (U6) and any model-assisted gap *filling*, behind the budget kill-switch, pilot-first; U7's optional regeneration at a ~$0.15/item baseline `[DOC-STATED]`.

The governing insight, in the project's words: discovery compounds but cost does not, because the flywheel spins on a deterministic substrate and only synthesis is metered. `[CONFIRMED]` `recursive-compounding-discovery-2026-08-10.md`

**Execution model, operator ruling 2026-08-10:** corpus-wide passes are on-demand and operator-scheduled, weekly or monthly, **default off, never always-on**; every firing is kill-switched and bounded. `[DOC-STATED]`

## 11. What went wrong in the session that produced this document

This section is not confession, it is load-bearing. Every item below is a mistake that cost the operator real time, and each one now has a rule attached. A session that repeats any of these is not making a new mistake, it is failing to read.

The unifying mechanism, stated once: **every failure here came from acting on a plausible model instead of reading the thing that settles it.** Not one of them required cleverness to avoid. Each required opening a file.

### 11.1 The loader was named after a reserved command

The memory skill was named `resume`. `/resume` is a built-in UI command in both Claude Code and Cowork, so typing it opened the session picker and the skill never loaded, in any environment, ever. This was not intermittent. It never worked once.

**Consequence:** every Cowork session for days started with no project memory and answered from the application database or from its own context, while appearing to work normally.

**Rule:** never name a skill after a built-in command. Before naming one, check it against the reserved set. A skill that cannot be invoked is worse than no skill, because its existence stops anyone building the thing that would have worked.

### 11.2 The loader hardcoded a container path

It named `/root/work/dotfiles` as the vault. That path existed in exactly one Cowork container, by accident of an early clone. Every fresh container found nothing there and proceeded anyway.

**Rule (now A0):** the loader locates its own repo — existing clone by remote URL, filesystem search, fresh clone from GitHub, desktop bridge — and if all four fail it **says it has no project memory and stops**. It never answers architecture, cost, or status questions from the database. The database is not the memory.

### 11.3 Fault was attributed to the data layer instead of the access layer

The working theory for some time was that the vault or Obsidian was broken. The vault was never broken. Content was committed, current, and correct. What was broken was the loader, twice over.

**Rule:** when memory appears missing, verify the *access path* before doubting the *content*. `git log -1 origin/master` on the vault answers this in one second and was not run.

### 11.4 The working tree was trusted as current state

The skill said "read the repo." A container was found on branch `dead-code-sweep`, **ahead 1 and behind 7**, where `git pull --ff-only` refuses outright. Reading it would have served three-day-old state as current, with no signal to the reader.

**Rule (now A0):** read memory via `git show origin/master:<path>`. Never the working tree. Report the branch and its divergence in the resume line so the operator can see the basis.

### 11.5 The correction list rotted, and no rule required checking it

The skill's own standing-corrections section still named the column `result_content_excerpt` after migration 264 renamed it to `result_content` **the same day**. A cache with no expiry policy.

**Rule (now B8):** verify Section C against `origin/master` before quoting it. Corrections that name a column, path, or line number get confirmed, not recited.

### 11.6 A main-checkout commit was instructed, violating enforced doctrine

Three files were staged in the operator's main checkout via the device bridge, and the operator was handed a copy-paste block ending in `git commit` there. **RD-19 (`docs/doctrine/worktree-isolation.md`) has been enforced since June** and its scope explicitly includes commit: *"An agent that finds itself in the main checkout stops and reports, it does not operate there."*

The `pre-commit` hook blocked it. A Claude Code session then landed the identical work correctly through a worktree as PR #466.

**The mechanism deserves naming precisely.** `docs/decisions/` was searched for the column question. `docs/doctrine/` was never searched for the git question. The right habit was applied to the wrong directory.

**Rule (now B9):** never commit in the main checkout and never instruct the operator to. The sanctioned path is a worktree branch and a PR. Never `--no-verify`. **Advice that routes a blocked action through a human is the same violation, laundered.**

### 11.7 Instructions were shipped without being run

The operator was given `git reset && git pull --ff-only`. It was insufficient: `git reset` unstages but leaves file contents, so untracked and modified copies blocked the fast-forward and the pull failed. Separately, a `git show origin/master:<path>` comparison in Git Bash silently returned nothing because **MSYS mangles `:` into `;`**, producing a false "DIFFERS" that was a tool artifact, not drift.

**Rules:** (a) an instruction handed to the operator is a proposal that has not been tested; say so, or test it. (b) On Windows Git Bash, any command containing `rev:path` needs `MSYS_NO_PATHCONV=1`. (c) A comparison whose input command produced **no output** is not a difference. It is a broken command. Check the input before reporting the result.
