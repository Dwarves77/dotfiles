## 2. Legend

- guard: the first principal check reached in control flow, with file:line (route.ts means the route file itself). "none" means no principal check precedes the first read or write. Guard strings: `requireAdminRoute` = Bearer session, 60/min limiter, then profiles.is_platform_admin on a service-role client (src/lib/api/route-guard.ts:331-349); `requireUserRoute` = Bearer session plus limiter (:304-314); `requireCommunityRoute` = cookie or Bearer session plus limiter, returns a user-bound client (:318-328); `workerAuthGuard` = x-worker-secret compared in constant time (src/lib/api/worker-auth.ts:394-421).
- class: admin (platform admin gate), worker (shared secret), session (a session is required, roles as named), none (no guard); for pages admin-page, page-session (in-page session check), page-proxy (no in-page check; proxy session gate only), page-public.
- roles named: the role or ownership check the route or its lib performs before a write, with line; "none" means the route names no role; "org membership only" means the org id is resolved from org_memberships and the role column is not read.
- client: which client performs the DB calls and where it is built. "service role" = getServiceSupabase() (src/lib/supabase-service.ts:31) or a createClient with SUPABASE_SERVICE_ROLE_KEY; "user-bound client" = the cookie or Bearer client returned by requireCommunityRoute (RLS applies); "cookie-bound anon-key client" = createSupabaseServerClient (src/lib/supabase-server-client.ts), RLS applies.
- svc-write: none (no service-role write in the method); gated (service-role write behind an admin or worker gate); role (service-role write behind a named role check); norole-self (service-role write with no role check, keyed to the caller's own id or to a row the caller just created); norole-shared (service-role write with no role check on shared or org-wide rows).
- write before guard: yes only if the first write line precedes the guard line in the handler body. For guards inside a shared helper the handler body was read: it only parses the request before calling the helper.
- anon: to-guard (the proxy lets an anonymous request into the handler and the guard refuses it), open (the handler serves an anonymous request), public (a PUBLIC_ROUTES page or the auth callback), proxy-gated (a page; the proxy redirects an anonymous request to /login, route-policy.ts:106-108).
