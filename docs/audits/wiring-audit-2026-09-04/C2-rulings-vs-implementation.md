## 4. PR classification (107 PRs, `_prs.txt`)

Method: for each of the 107 commits, the changed-file list was pattern-matched by path (not by reading every diff in full) — `fsi-app/src/app/**` (excluding `/api/`), `fsi-app/src/components/**`, and `*.tsx`/`src/**/*.css` count as **customer surface**; `fsi-app/src/app/api/**`, `fsi-app/scripts/{producers,turns,connections,classification,maintenance,mint,forward-events}/**`, and `.github/workflows/**` count as **runtime**; `fsi-app/.discipline/**`, `fsi-app/scripts/verify/**`, `docs/dispatches/**`, and `fsi-app/scripts/harness-runs/**` (the run-artifact ledger the codebase itself calls "the harness," per rule 17) count as **harness/discipline**; a PR is **docs only** when it touched nothing outside `docs/`. "Customer surface" and "runtime" are not mutually exclusive (a train PR routinely touches both); "harness/discipline layer only" and "docs only" mean *nothing else* was touched.

| Category | Count (of 107) |
|---|---|
| Touched a customer surface (`src/app` pages/components, `.tsx`/`.css`, or API routes the UI calls) | **30** |
| Touched a runtime (producers, mint/turn/connections/classification/maintenance scripts, or a `.github/workflows` file) | **76** |
| Harness/discipline layer only (only `.discipline/`, `scripts/verify/`, `docs/dispatches/`, or `scripts/harness-runs/` run-artifacts changed — no product code) | **7** |
| Docs only (nothing outside `docs/` changed) | **6** |

The remaining 13 PRs (harness-only + docs-only = 13 of 107, ~12%) moved no product code at all — pure run-artifact landing or memory/plan commits. The other 94 PRs (~88%) touched runtime and/or customer-facing code, weighted toward runtime (76) over customer surface (30) — consistent with this being a population/flywheel-heavy two weeks rather than a UI-heavy one, and worth cross-checking against AUDIT-C1's per-surface findings for whether that 30 actually reached a wired, navigable page.
