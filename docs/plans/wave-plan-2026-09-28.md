# Wave plan, 2026-09-28: finish the build in parallel waves

Why: operator, 2026-09-28, "At this current rate we will not have this build finished for months and that's unacceptable". This plan replaces the one-to-two-lane rhythm with waves of 6-8 lanes whose write sets do not overlap. Sources: [build plan workstreams 1-16](./build-plan-2026-09-25.md), [tool-gap register](./data-machine-tool-gaps-2026-09-25.md), [close note](../ops/session-log.d/2026-09-28-coordinator-close.md). Priority order stays R14: the data machine first, surfaces second.

## Run rules (every brief carries these)

1. Do the work yourself; do not use the Agent tool (memory no-nested-agents).
2. Own worktree under `.claude/worktrees/`; no node_modules links (#815); never `--no-verify`.
3. Run every touched test the way CI does (no-npm resolver for `*.test.mjs`, `SUPABASE_*` unset) before pushing; push ONCE; if CI is red, stop and report the local-vs-CI difference instead of pushing again.
4. Test what you build: a real run (dry dispatch or dry CLI) with its `harness_runs` row read back.
5. R14: no live site-data writes. Schema DDL for tools goes to the coordinator as SQL first.
6. Design questions the specs/ADRs answer are answered in the brief with citations; a lane stops only for a question they do not answer.
7. Each lane's first report includes a size estimate (files, tests, runs) so the plan gets a measured finish line. No dates are invented before that.

Merging: a standing coordinator loop merges any lane PR whose checks are all green, then confirms master CI on the merge commit.
