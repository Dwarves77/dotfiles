### Section 4 - category 53: a worktree reaches the shared install through ONE link beside the worktrees, never a link inside a worktree

[CONFIRMED, 2026-09-25 and 2026-09-27] New linked worktrees under `.claude/worktrees/` had no `fsi-app/node_modules` (gitignored, never materialised by `git worktree add`), the lane contract forbids `npm install` in a lane, and the pre-push fitness runner then reported F9, F10, F11 and F12 as violations (their selftests import npm deps) or hung. ### Section 4 - category 54: workflow_run chains are checked against GitHub's own documented 3-level limit, not assumed reliable at any depth

### Section 4 - category 58: a CSS color is never built by concatenating digits onto a var(--token) reference

[CONFIRMED, lane R12-13, 2026-10-01] CF-BROKEN-2 / A2bc finding A6: 24 sites across `src/components/sources/**` and `resource/IntelligenceMetadataStrip.tsx` built an inline-style tint by string-concatenating a bare percentage onto a `var(--token)` reference, e.g. `"var(--color-error)" + "15"` produces `"var(--color-error)15"`. That string terminates the var() reference at its closing paren; the trailing digits are not CSS syntax of any kind, so the browser drops the whole declaration and the tint never painted. A second, independently-confirmed instance of the same defect appeared in `timeline-dot-styles.ts`'s `nextDotStyle` (the "next milestone" ring): both live call sites (`Timeline.tsx`, `ListRow.tsx` via `MilestoneTimeline.tsx`) passed `band.cssVar` (a var() reference) where the function appends a raw two-digit alpha suffix, the same shape via template-literal interpolation instead of `+` concatenation. The root cause in both shapes is the same: a `var()` token is treated as if it were an opaque color literal that tolerates a suffix, when it is a complete, self-terminating CSS value.

**No source file builds a color by concatenating digits directly onto a `var(--token)` reference (`"var(--token)" + "NN"` or the equivalent template-literal shape); that string is not valid CSS and the browser silently drops the whole declaration.** The fix is root cause not symptom, reusing what the codebase already had rather than adding a parallel mechanism: `src/lib/tint.ts`'s `tint(cssVar, percent)` builds `color-mix(in srgb, var(--token) percent%, transparent)`, a real CSS value, for the inline-style sites; the two `nextDotStyle` call sites were repointed from `band.cssVar` to `band.hex` (the raw hex literal `UrgencyBand` already carried, reuse-before-construction rather than adding a new field). Fitness function F62 (`no-css-var-concat`) is the static gate: it scans all `src/**/*.{ts,tsx}` for a `var(--token)` reference immediately followed by 1-3 digits with no delimiter, catching both the `+`-concatenation and template-literal forms, while explicitly not matching a real `color-mix()` argument (space before the number) or a comma-separated list. `tint.ts` itself is exempt (it documents the defect shape verbatim in its own header comment, by design). Negative-tested per Section 4's attack-not-presence discipline: RED cases (the `+`-form, the template-literal form, the already-joined-literal form) and GREEN cases (the fixed `tint()` call, a real `color-mix()` argument, a bare `var()` with no digit, `nextDotStyle` with a hex literal, `tint.ts`'s own exemption), plus a LIVE sweep of the real tree. Invariant RD-90.
