## Section 4: Remediation Strategy by Category

Eight confirmed categories with full worked examples in Section 7:

1. **Batch resilience** — long-running scripts need retry/reconnect/idempotency/rate-limit/progress primitives extracted into a shared library
2. **Sweep methodology** — sweeps must enumerate the surface (Glob, schema query, equivalent) before claiming completeness; recall-based or pattern-matched enumeration misses items silently
3. **Type-system drift** — schema-vs-code compatibility breaks require compatibility shim + per-consumer migration, not flag-day rename
4. **API contract gaps** — silent failures from format/version mismatches (URL canonicalization, timestamp normalization, identifier matching across system boundaries) need primitive extraction
5. **Tool reliability** — agent-layer tools (Glob, etc.) sometimes return inconsistent results across contexts; defensive discipline + root-cause investigation when bandwidth allows
6. **Architectural codification** — when a model exists as transcript or operator memory but not as canonical reference, encoding it as a skill is the class fix; prevents future drift and reinvention
7. **Worktree cleanup discipline** — worktree removal is multi-step (git worktree remove + filesystem rm + config registry sweep); audit dispatches that read config without filesystem validation produce false positives
8. **Roadblock resilience (source fetch)** — *roadblock → bounded alternative-search → same-floor qualification.* When a declared primary source roadblocks (timeout, JS/Cloudflare stub `<200ch`, 403/404, wrong-language-only), the pipeline must SEEK a replacement, not give up — the mechanical form of env-policy's "find replacements when canonical sources break" (Operating Principle). The non-negotiable invariant: alternative-search widens which sources you TRY, never which tier QUALIFIES — a found alternative passes the SAME `buildResolver` tier resolution + the SAME per-type authority floor, so a sub-floor alternative is a corroborator/relabel input at best, NEVER a primary (the item still honest-exits/counsel-holds). This structurally forecloses the F1 regression (primary times out → search returns a law-firm explainer → secondary grounds a reg fact): promotion is emergent from clearing the unchanged floor, never a fallback action. Bounds: ~20s/fetch, ≤3 alternatives, no retry on a roadblocked URL (retrying a dead URL is the 120s×5 waste that burned 10 min on commerce.gov.in). The roadblocked-vs-partial line is load-bearing — a real-but-partial page (`≥200ch` in-language) is an HONEST PARTIAL (use it; missing facts → counsel), not a roadblock; a false-roadblock that swaps a valid primary for a search hit is a provenance downgrade, worse than a thin real primary, so ambiguous → "primary succeeded." The counsel-hold record splits `NO_SOURCE_FOUND` (searched, nothing fetchable) vs `NO_SOURCE_QUALIFIED` (found N, all sub-floor) and records `alternatives_tried` + `best_resolved_tier` as a durable integrity_flag, so a counsel-hold provably means "searched + exhausted," not "never looked." This is the build-out of the Section 2.1 recovery-triage diagnostic (check for a stored pool / seek a replacement before concluding). Implementation: `src/lib/sources/primary-fallback.mjs` (`detectRoadblock` pure + CI-unit-tested; `fetchPrimaryWithFallback` dep-injected), wired via `canonical-pipeline.fetchPrimaryDeep` into both `generateBrief` and the re-ground path (`groundStep`; the former standalone `phase2-reground.mjs` runner was retired in the 2026-07-13 snapshot-first rebuild).

9. **Producer-consumer orphan (the half-slice defect)** — a writer with no reader (a table/column the app writes but nothing consumes — dead output) or a reader with no writer (a surface consuming a never-written field — dead input) is the HALF-SLICE defect class: a feature built on one side of the producer-consumer boundary and never closed on the other. Every prior audit found these BY HAND (`source_trust_events` written many ways read zero, the notification layer's write-only tables, the mig-007 forum layer); that hand-check is now a standing mechanical gate. The rule: a table the application writes MUST have a consumer, OR be allowlisted as a legitimate terminal sink (an append-only audit trail, or a writer that precedes the reader a named later phase builds) WITH a stated reason and a review-by-phase tag — never silently excluded, and the allowlist is itself audited (a stale entry whose table is gone or is no longer an orphan is reported). The detector is deliberately CONSERVATIVE — it gates only on high-confidence zero-reader-anywhere write-orphans (a reference in any SQL `FROM`/`JOIN`/`REFERENCES` counts as a reader, so the gate never cries wolf and never gets muted); reader-side never-written-field findings are REPORTED for phase scoping, not gated. The first-run report feeds Phase 7's zero-reader verification and does not itself authorize deletion. Implementation: `.discipline/governance/producer-consumer-orphan.mjs` (pure core + git-tracked scan + first-run report), wired as fitness function F14, invariant RD-9.

10. **The transport hold gate (fetch-primitive scrape-hold gate)** — a "scrape hold" enforced only by DELETING the credential (BROWSERLESS_API_KEY) fails SILENTLY and ambiguously: a held fetch throws "key not configured" — indistinguishable from a genuine misconfiguration — and nothing observes that the hold blocked a fetch. The class fix makes the hold a FIRST-CLASS, MECHANICAL, OBSERVABLE gate at the SINGLE canonical fetch primitive: `assertFetchAllowed(url)` throws a named `FetchHoldError` while the hold is engaged (`SCRAPE_HOLD`), so "scrape hold LIVE, zero fetches" is enforced in code, not by credential-absence. Because the fetch is single-homed (`canonical-fetch.mjs::browserlessFetch`, the "one implementation so ~10 sites cannot diverge" primitive), gating IT gates every call site at once; a raw Browserless content fetch anywhere else BYPASSES the gate and is forbidden. The hold DEFAULTS to LIFTED (an explicit operator control — engaged with `SCRAPE_HOLD∈{1,on,true,engaged}`) so wiring the gate does not silently break prod fetching; the operator LIFTS the hold (`SCRAPE_HOLD=off`) only when the scrape cadence is set, which is what unblocks seek-more and new site content. Paired with the hold: a canonical-URL pre-fetch cache (the `url-canon` single home keys the cache so equivalent URLs share one entry, with a per-source TTL) and per-run fetch telemetry (hit/miss/hold-blocked/bytes), so resumed fetching is observable and does not re-fetch what it just fetched. Implementation: `src/lib/sources/fetch-hold.mjs` (pure core, red-then-green) wired at `canonical-fetch.mjs::browserlessFetch`; fitness function F16, invariant RD-11.

11. **The size-cap doctrine (no silent slice on the grounding path)** — the size-axis analog of the spend ceiling. A cap that SILENTLY slices content on the capture→synthesis→grounding→judge path is a completeness defect that fails CLOSED (false holds, missed coverage, wasted spend) and is invisible: `GROUND_SECTION_MAX_CHARS=12000` silently hid the back of every brief section from the grounder, so a binding fact past 12KB was never seen (17 items carried a >12KB section; max 32KB). The rule: EVERY size cap on that path is either **sized so it never binds in normal operation**, or **fails LOUD** (a surfaced wall — `recordTruncation` → coverage_gap integrity_flag + item held with a named reason) when it binds. Silent slicing is forbidden. The category-2 fix retired the silent section slice — sections reach the grounder COMPLETE up to a 200KB hard ceiling (trivial vs the 560KB source budget) that SURFACES if it ever binds. Every cap on the path is enumerated + classified in a cap-inventory (`docs/design/cap-inventory-2026-07-06.md`); a CI guard REDs any new unregistered/silent cap so the class cannot re-enter. Implementation: `src/lib/agent/section-grounding.mjs` (`prepareSectionForGrounding`, pure + red-then-green) wired at `canonical-pipeline.ts` groundBrief; fitness function F17 (cap registry + grep-guard), invariant RD-12.

12. **The error-body groundability gate (never ground a FACT to a failed fetch)** — the capture layer stores failed fetches (bot walls / 403 / 404 / Request-Access blocks / nav shells) as "source content"; when grounding then copies a verbatim span out of that body, a FACT is "grounded" to a 404 or a Cloudflare challenge page — the **fabricate-via-error-page** moat breach (2 verified corpus items carried a tier-1 FACT whose span was literally "Page Not Found"; corpus-wide, 51+ FACT claims across 27 items grounded to error bodies). This is a completeness+integrity defect distinct from the size caps: the capture is junk, not truncated. The class fix reuses the single-home `isErrorBody` (entity-gate.mjs) at the grounding pool's origin: `partitionErrorBodies` splits the fetched pool into usable vs error-bodies, and an error-body capture MUST NEVER enter grounding input, the floor pool, or slot-forcing nomination (all three derive from the one `fetched` pool, so gating it once gates all three). Excluded captures are SURFACED (per-item warn + a `source_issue` integrity_flag naming the failed-fetch URLs for re-fetch at hold-lift), never silently dropped. Paired: the necessity gate REJECTS a paid re-ground of an item whose remaining failure classes can only be satisfied by content behind a failed-fetch capture (junk-pool, event-bound to re-collection — stop paying to ground unwinnable pools). `isErrorBody` computes at read time (render-derive, zero DDL; migration 147's `sources.fetch_status` is the durable home once the DDL window lands). Implementation: `src/lib/sources/entity-gate.mjs` (`partitionErrorBodies`, pure + red-then-green with real 404/bot-wall fixtures) wired at `canonical-pipeline.ts` groundBrief; invariant RD-13.

13. **The transport escalation ladder + write-side error-body gate (transport failure is never terminal, never stored)** — RD-13 gates READ-side consumption (an error body cannot be GROUNDED); this is the WRITE-side complement + the per-failure-class escalation ladder, closing the point where the junk pool FORMS. The decisive finding: even with RD-13, when both transports failed the capture layer STILL STORED the error body as `agent_run_searches.result_content_excerpt` whenever the two detectors disagreed (`detectRoadblock` is head-scoped ≤600ch; `isErrorBody` scans 2500ch — a nav shell with a 403 marker past char 600 read as "OK" to the write path, so it was stored and only RD-13 later refused to ground it). The class fix is a mechanical, per-class LADDER at the single primitive and a CAPTURE-time gate: **(a)** the canonical-URL cache first (RD-11 `fetch-hold.mjs`); **(b)** a block / bot-wall on one transport MUST try the OTHER, in EITHER direction (it fires on the 403 class, not only `cdn_block`); **(c)** a JS-shell / soft-404 (a 200 whose body is a client-render placeholder) routes to the Browserless render path; **(d)** an API host (federalregister.gov + eCFR) MUST route to its OFFICIAL JSON API, NEVER the HTML page (the HTML returns "Request Access" to scrapers) — a host→transport selection; **(e)** a genuine 404/410/soft-404 after the ladder emits a SEEK-MORE task (alternate-URL discovery) and MUST NOT store an error body; **(f)** ladder exhausted on blocks/walls records the verdict (`sources.fetch_status` when migration 147 lands; the integrity_flag pattern until then) and the item HOLDS with the named reason NO_REACHABLE_SOURCE, event-bound to re-collection at hold-lift. The write-side gate is the class kill: `isErrorBody` (single home) evaluated at CAPTURE time — an error body is NEVER stored as source content into `agent_run_searches` — plus the capture-time superset that also refuses the Request-Access permission wall + JS shell `isErrorBody`'s marker set misses; the excluded set is SURFACED (a `source_issue` integrity_flag), never silently dropped, and a junk-only capture HOLDS rather than fabricating a brief over an error page. **The doctrine: transport failure is never terminal and never stored; quarantine is the honest state only for genuine ungroundability after mechanical exhaustion, named and event-bound, never a fetch-failure artifact.** The pure decision logic (classifier, host→transport selection, the `escalateFetch` orchestrator, the `captureForStorage` write verdict) lives in a testable module with the transports dependency-injected so NO real fetch happens in tests. Implementation: `src/lib/sources/transport-escalation.mjs` (pure + red-then-green with the four real adjudicated fixtures — SFC 403, EUR-Lex 404, customs.go.jp JS shell, federalregister Request-Access) wired at `canonical-pipeline.ts` generate/refresh/ground pool-INSERT sites; invariant RD-14.

14. **Worktree isolation (agent branch/checkout/merge ONLY in the assigned worktree)** -- the class fix for the parallel-agent development-process failure where a sub-agent runs a branch op in the wrong checkout. **The doctrine (verbatim, RD-19): "Agent branch/checkout/merge operations occur ONLY in that agent's assigned worktree. The main checkout is the orchestrator's exclusive surface. An agent that finds itself in the main checkout stops and reports, it does not operate there."** The incident: a sub-agent ran `git checkout -b <branch>` in the MAIN checkout (`C:/Users/jason/dotfiles`) instead of its assigned worktree under `.claude/worktrees/`; that moved the main checkout's HEAD onto the agent's branch, so subsequent orchestrator commits landed on the wrong label and had to be manually untangled. The PreToolUse skill-gate did NOT catch it because PreToolUse was session-scoped and did NOT fire inside subagents/workflows when this was verified on 2026-06-07 -- the same out-of-repo boundary that made the action-time gate a main-session-only backstop at the time. [REFUTED 2026-09-19, lane M3]: it now DOES fire inside sub-agents (the main checkout's own `.gate-audit.log` recorded 11 denials of a sub-agent's own Edit/Write calls), and lane G1 (issue 754) made the skill gate judge the acting agent's own transcript, closing the gap this incident exploited. The 2026-06-07 finding stays accurate as history; it no longer describes the present, and the dual belt-and-suspenders design below remains correct regardless (the git-hook legs still fire where the skill-gate historically could not, and now both legs fire). The class fix is DUAL, fail-closed, belt-and-suspenders (mirroring the RD-11 transport-hold dual pattern): **(belt)** the PreToolUse skill-gate surfaces every `git checkout/switch/branch/merge/rebase/worktree add` op for conscious confirmation against the doctrine -- it fires only in the MAIN session, so it catches the ORCHESTRATOR's own stray ops; **(suspenders)** git-hook legs that fire REGARDLESS of session type (git hooks run in git's invoking process, so they DO fire inside a sub-agent's Bash where the skill-gate cannot): a `post-checkout` hook HARD-FAILS loudly (naming the doctrine) when an AGENT context performs a branch checkout in the MAIN checkout -- detection + alarm, since git already moved HEAD and the hook cannot undo it -- and a `pre-commit` hook BLOCKS (aborts the commit) when a commit is attempted in the MAIN checkout under an agent context OR while the checkout sits on an agent-owned branch (`worktree-agent-<hex>`/`agent-<hex>`), which is exactly the corrupted state that let orchestrator commits land on the wrong label. The DETECTION SIGNALS are single-homed in a pure module: WHERE = main-checkout-vs-linked-worktree via `git rev-parse --git-dir` differing from `--git-common-dir` (a linked worktree's git-dir is under `<common>/worktrees/<name>` -- zero-false-positive, no env needed); WHO = the `CLAUDE_CODE_CHILD_SESSION` env marker the harness sets truthy for sub-agent sessions and leaves absent for the orchestrator (`AI_AGENT` is present in BOTH and does NOT discriminate, so it is NOT used). The block fires ONLY on a positive WHO signal so the orchestrator's legitimate main-checkout work is never blocked (fail-closed on the violation, not on ambiguity); the pre-commit branch-name belt is the env-independent backstop for the residual where an agent's env lacks the marker. Implementation: `.discipline/governance/worktree-isolation.mjs` (pure decision logic -- `isMainCheckout` / `isAgentContext` / `branchLooksAgentOwned` / `evaluateCheckout` / `evaluateCommit` / `isBranchingGitCommand`, red-then-green in `worktree-isolation.test.mjs` with both the RED main+agent block and the GREEN worktree/orchestrator pass) consumed by the `post-checkout` + `pre-commit` hook scripts (via `worktree-isolation-hook.mjs`, installed the governed way by `install-hooks.mjs`) and the PreToolUse skill-gate belt. A branch/checkout/merge/rebase op by an agent anywhere other than its assigned worktree is forbidden, and a commit in the main checkout under an agent context MUST be blocked. Invariant RD-19.

15. **The generation pause split (pause is prohibition, dormancy is schedule)** — RD-11 gates the FETCH primitive; this is the GENERATION-preflight sibling, same class fix: an operator-control gate that separates a PROHIBITION from a SCHEDULE. The incident (2026-07-12): `isGloballyPaused()` (cadence-off OR emergency-stop) gated generation as one boolean, so the F16-signed manual-intake path — authorized to FETCH through the hold (RD-11) — could MINT but never GROUND in the dormant pre-launch state it was built for (two live runs halted at FLOW 2/8, $0). The class fix is a single pure primitive, `evaluateGenerationPause(scrape, caller)` (`src/lib/api/pause.ts`), splitting the two conflated states: **emergencyPaused** (`global_processing_paused`) is a HARD stop for EVERY caller — the operator's stop is inviolable, no caller identity overrides it; **cadence==='off'** is DORMANT and halts AUTONOMOUS generation only — an F16-signed manual caller (`manual-intake-run`) proceeds, since an operator-fired run IS the bidding. The FETCH gate (`isGloballyPaused`) is unchanged; the downstream integrity gates (data-audit-block, daily-cap, per-type floors, grounding judge) bind EVERY caller always — no caller identity ever bypasses them. The mechanical proof is the red-then-green pair `generation-pause.npmtest.mjs`: the signed manual caller PASSES cadence-off, and is BLOCKED under emergencyPaused. A companion stop-authority guarantee — a live operator stop flag is inviolable and no agent may ALTER it — is backstopped by the `system_state` operator-control credential trigger (Unit 2a). Implementation: `src/lib/api/pause.ts::evaluateGenerationPause` (pure) consumed by `generate-brief.ts::preflightStep`; invariant RD-21.

16. **The source-link mint invariant (a mint cannot produce a source-less LIVE item)** — the Layer-1/Layer-2 model says intelligence items live INSIDE sources; an item with no `source_id` cannot ground (grounding grounds a brief against the item's source). The incident (2026-07-12): the manual-intake path (`runIntakeCycle`) minted eFTI 2020/1056 + waste 2024/1157 from `{title, source_url}` with NO source resolution, so both were source-orphaned and walled at `no source_id` — the T9 8/8 proof halted at 4/8 not on the gate but on this upstream gap. The autonomous scan path already resolves `source_id` by canonical URL against the registry at stage time (`scan/route.ts`); the manual path skipped exactly that step. The class fix is a single gate at the ONE mint home so ALL callers are covered: `mint-item.ts::sourceLinkDecision` (pure) — a caller-preset `source_id` is trusted; an unresolved `source_url` is REJECTED-with-reason (register the source first, no silent orphan, no auto-registration); a registry read error fails CLOSED. The mechanical invariant is dual: the chokepoint reject (proven red-then-green in `mint-source-link.npmtest.mjs`) AND a live-data audit (`scripts/verify/source-link-audit.mjs` + pure core `source-link-invariant.mjs`) that fails on any source-less LIVE row beyond the documented pre-cutover grandfather (the two T9 orphans, whose re-sourcing is Unit 3). Companion (Fix B): a STRUCTURAL ground-failure class (`ground-failure-class.mjs::groundRetryPlan`) routes `no source_id` STRAIGHT to held-for-re-source, skipping the two futile re-ground/re-research passes, and the erase step is relabeled honestly (brief-nulled-held, not "erased" — it never archived). Invariant RD-22.

17. **The pause-flag one-writer (structural enforcement, no credential, no manual step)** — human intervention is never a solution; a system manages the problem structurally. The FIRST attempt at binding the `system_state` stop flags (Unit 2a, migration 201 original) used a dedicated `operator_control` DB role + `OPERATOR_CONTROL_DATABASE_URL` secret — which required a MANUAL operator step (provision the login role, hold the secret, scope creds out of the agent env). That is a workaround, not a fix (operator ruling 2026-07-12: "human intervention should never be a solution"). The correct design is three structural layers, fully automated: **(static)** an F20 fitness function (RD-13 pattern) fails CI on any direct write to `global_processing_paused` / `scrape_cadence` in src outside the sanctioned admin route — a second writer cannot be merged; **(runtime)** migration 201 REWORKED — the ONE sanctioned writer is the SECURITY DEFINER RPC `admin_set_pause_state`, which declares a transaction-local marker `app.pause_flag_writer`; the BEFORE UPDATE trigger `guard_pause_flag_writer` BOUNCES any flag change lacking the marker, so a generic service-role `UPDATE system_state SET global_processing_paused=…` (an agent's ad-hoc flip, the exact 2026-07-12 abuse) is rejected `insufficient_privilege`; **(detection)** the `system_state_flag_audit` table logs every authorized write's declared origin. No role, no secret, no manual step. The bounce is proven red-then-green on a SYNTHETIC temp table in a rolled-back transaction (`scripts/verify/pause-flag-guard-proof.mjs`) — the live flag is never written under any path, including the test. Invariant RD-23.

## Section 4.6: Retrieval before generation (check existing work/data before re-deriving)

Reuse-before-construction (the platform doctrine) is scoped to CODE. This is its WORK-PRODUCT / DATA sibling, the same class fix one level out: **before any generation, discovery, or re-derivation step, the first action MUST be a retrieval check — does this output already exist?** Check the obvious stores (another column on the row, the item's own `agent_run_searches` pool, `provisional_sources`, the `sources` registry) AND prior-session work; use what is found; generate only the genuine residual. Treat "the prior pass produced this" as a retrieval problem first, a regeneration problem only if retrieval comes up empty. It binds hardest before any batch that SPENDS.

**Why it earned a rule.** It slipped twice in one session (2026-06-23): a backward re-point / re-discovery was proposed for the reg corpus when the enacted-text URLs were ALREADY discovered by the prior deep-dive generate and stored as corroborators in each item's `agent_run_searches` pool — one decision from spending to re-discover URLs already in our own database; and the enacted twins were not checked until a later pass surfaced them. The principle existed but was scoped wrong: reuse-before-construction covered code, verification-before-authorization's read-only-first was framed for dispatch WRITES, diagnose-before-fixing is general spirit — none said "the answer may already exist; check before (re)generating." With no mechanical gate it slipped under execute-the-plan momentum. The class fix is to state it as its own discipline (here) + register it as invariant RD-8 + carry it in CLAUDE.md's Reuse-before-construction doctrine (extended to work-products/data, 2026-06-23).

**Recognition signals fired.** Signal 1 (recurrence: re-point + dedup-twins, two slips one session); signal 4 (reinventing-the-wheel: any future discovery/generation step would re-derive an output already persisted). Class confirmed; the fix is doctrine + invariant, not a primitive — the "retrieval check" is judgment exercised at planning time, not a single extractable function, hence RD-8 is exempt like RD-2/RD-3. The backward promote-from-pool operation is the worked example: re-point = promote the already-stored enacted URL, not re-discover.

### The spend chokepoint (generation-side dedup-before-ground) — the mechanized sibling of RD-8

RD-8 is the judgment-time retrieval check; this is its MECHANICAL enforcement one level out, at the point of SPEND. It earned a rule the same way RD-8 did — necessity was never mechanized and generation spend had no chokepoint, so every new runner started ungated (third instance in one program: a perf-wave quote, a GLEC-duplicate ground, and the proof-batch routing that produced a void $53 full-set quote — each caught only because the operator asked "did you check the free lever first?"). That question being the detection mechanism IS the defect (the autonomy principle: the platform must not need a human to ask). The class fix is a single spend client every model call routes through: it **MUST** require a SpendTicket (a ticketless call throws), it **MUST** reject a per-item ticket whose failure set is fully deterministically-resolvable (the deterministic-lever necessity gate — do the $0 thing first) OR whose standing disposition is DELETE (a held dup-loser is never paid to regenerate), and it **MUST** enforce the budget ceiling in code (the ceiling stops being relay discipline). No Anthropic API call may exist outside the spend client and its sanctioned transport, beyond a reason-bearing, review-by-phase-tagged SHRINKING allowlist that is itself audited (a stale entry is RED). Enforced by fitness F15 (grep-class, red-then-green) + the spend-guard selftest + invariant RD-10; this is the generation-side analog of the intake dedup-before-ground gate.

### Operator-priced spend + data-existence-before-acquisition (2026-07-13) — the two-mechanism spend model

The spend chokepoint above evolved (operator ruling 2026-07-13) into exactly two mechanisms: operator-priced line approvals (the sole authorization) and spend-watch (a pure alarm). All standing dollar figures are retired as limits.

**Operator-sets-cost: the paid path MUST carry an operator-priced line.** Spend authority is solely the operator's per-line price — an operator-set cost plus an inventory-miss citation; the machine never proposes, defaults, or anchors a price, and an approved line halts at the operator-set cost (no default tolerance unless the line carries one). Every standing dollar figure — per-item breaker, daily cap, monthly ceiling — is RETIRED as a limit; the gauge reports month-to-date actuals as information only, never as a fraction of a target (no denominator). Spend-watch is a pure alarm: any paid `agent_runs` row not traceable to an operator-priced line, at any amount, is the anomaly. Enforced by invariant RD-31 (the priced-line gate + spend-guard selftest + the verify-item paid-branch refusal).

**Data-existence-before-acquisition: no fetch without a cited inventory-miss.** No acquisition may fire without first proving the datum is absent from what we already hold (stored pools, snapshots, sections, prior captures); the paid path MUST refuse without an inventory-miss citation naming what was checked and the specific miss. Acquisition is always the named DELTA — the missing document or span-range — never a re-fetch of anything a pool already carries. This is the verify-before-acquire discipline made mechanical at the paid chokepoint. Enforced by invariant RD-32 (the priced-line inventory-miss requirement + the verify-item paid-branch refusal).
